# `link/` — the Lean machine held by OCaml, and the host core around it

The route-1 bridge: an OCaml process holds a Lean `RunMachine` (`src/OCaml5/Bridge.lean`, a
`Session`) as an opaque value and steps it one host decision at a time. On top of that,
the core of the effect-native daemon from
`docs/research/2026-09-04-effect-native-daemon-architecture.md` §1–§4: a bounded mailbox
per machine, one worker loop per domain, a router from machine id to owning domain, a
per-domain event ring, and the host that assembles N domains. Written to
`ocaml/STANDARDS.md`: a library with one component per file and a property list
at the head of each, thin drivers, generated files marked and regenerable, every claim in
`REPORT.md` behind a command.

## Layout

This directory is `ocaml/link/`. The Lean half lives in the repo's own source tree
(`src/OCaml5/Bridge.lean`) and is compiled by `tools/compile-bridge.sh`, not by `lake`;
`link/` is outside the workspace's `(dirs avatar server gen eff)` on purpose (it links the
Lean static libraries), so it is always built from inside it with `--root .`.

## Build and run (WSL Ubuntu, opam switch `effect4`: OCaml 5.1.1, dune 3.24)

```
# from Windows
wsl -e bash /mnt/c/Users/kokok/Dev/lean4-effect4/ocaml/link/tools/build.sh --test
wsl -e bash /mnt/c/Users/kokok/Dev/lean4-effect4/ocaml/link/tools/run-demo.sh
wsl -e bash /mnt/c/Users/kokok/Dev/lean4-effect4/ocaml/link/tools/run-bench.sh 200 3 20000
wsl -e bash /mnt/c/Users/kokok/Dev/lean4-effect4/ocaml/link/build-link.sh pFork 100

# inside WSL, from link/
bash tools/build.sh            # Bridge.o if Bridge.lean changed, the flag files, dune build --root .
dune build --root .            # once the flag files exist (they are what tools/lean-flags.sh writes)
dune test --root . --force     # the property tests
./_build/default/e4_demo.exe
./_build/default/e4_bench.exe [machines=200] [reps=3] [single-iters=20000]
./_build/default/e4_probe.exe [program=pFork] [fuel=100]
```

What the build does, in order: (1) `tools/compile-bridge.sh` copies `src/OCaml5/Bridge.lean`
to `~/Dev/e4-link/Bridge.lean` and runs `lean -M4096 -c` + `leanc -c -O3` only if the copy
differs from the last compiled one (a failed compile leaves no `Bridge.o`, so it retries); it builds
the Linux tree's static libraries with `lake build …:static` only if one is missing.
(2) `tools/lean-flags.sh` writes `c_flags.sexp` (`-I<toolchain>/include`) and
`lean_flags.sexp` (`-cclib` pairs: `Bridge.o`, the four Lean archives, the Lean runtime
and its bundled static libc++/libc++abi/libunwind/gmp/uv, in one `--start-group`), with a
digest of `Bridge.o` in a comment so dune relinks when it changes. (3) `dune build --root
.` in `ocaml/link/` — standalone on purpose: the estate's workspace lists `(dirs avatar
server gen eff)` and leaves this one to its own script. Set `E4_BUILD_DIR` to move `_build`
(e.g. to the Linux side).

The link recipe is `build-link.sh`'s: gcc + the system glibc; Lean's static libraries
named explicitly (`-lc++` would resolve to a shared libc++ the system lacks; `leanc` as the
driver links old-glibc stubs that clash with OCaml's `libasmrun`). The flags sit on the
executables (`link_flags`), not on the library: `c_library_flags` would also feed the
bytecode stubs `.so`, and `libleanrt`'s local-exec TLS cannot be linked into a shared
object. ocamlopt places command-line `-cclib` objects after the library's stubs archive,
which is the order a static link needs.

## The ABI

`lean_object*` arguments are OWNED by the Lean callee: the stubs `lean_inc` the session
before every call that keeps it alive on the OCaml side, and strings cross by copy in
both directions (`lean_mk_string` in, `caml_copy_string` + `lean_dec` out). Every Lean
call runs inside `caml_enter/leave_blocking_section` with no OCaml value in hand, so a
step on one domain never stalls another domain's stop-the-world.

| Lean export (`src/OCaml5/Bridge.lean`) | C stub | OCaml (`E4_bridge`) |
| --- | --- | --- |
| `e4_program_names : Unit → String` (newline-separated) | `caml_e4_program_names` | `program_names : unit -> string list` |
| `e4_load : String → UInt32 → Session` | `caml_e4_load` | `load : program:string -> fuel:int -> t` |
| `e4_name : Session → String` (the table name, `bytes`, or `!refused:<reason>`) | `caml_e4_name` | `name : t -> string` |
| `e4_program_hex : String → String` (canonical bytes as hex, `""` when unknown) | `caml_e4_program_hex` | `program_hex : string -> string option` |
| `e4_load_hex : String → UInt32 → Session` (decode, type, load; refusals by name) | `caml_e4_load_hex` | `load_hex : hex:string -> fuel:int -> (t, refusal) result` |
| `e4_step : Session → String → UInt32 → Session` | `caml_e4_step` | `step : t -> fuel:int -> decision -> t` |
| `e4_drive : Session → UInt32 → Session` | `caml_e4_drive` | `drive : t -> fuel:int -> t` |
| `e4_snapshot : Session → String` | `caml_e4_snapshot` | `snapshot : t -> string` |
| `e4_armed : Session → String` (comma-separated ids, arming order, `""` if none) | `caml_e4_armed` | `armed : t -> int list` |
| `e4_finished : Session → UInt8` | `caml_e4_finished` | `finished : t -> bool` |
| `e4_fibers : Session → String` (`id\tlive\|exited\ttoken\|-\tsuccess:<tag>\|failure\|-` per line) | `caml_e4_fibers` | `fibers : t -> fiber list` |
| `e4_trace_len : Session → UInt32` | `caml_e4_trace_len` | `trace_len : t -> int` |
| `e4_events : Session → UInt32 → String` (rows from the cursor, newline-separated) | `caml_e4_events` | `events : t -> cursor:int -> string list` |
| `initialize_Bridge`, `lean_initialize_runtime_module`, `lean_io_mark_end_initialization` | `caml_e4_init` | `init : unit -> unit` (once, main domain) |
| `lean_initialize_thread` / `lean_finalize_thread` (exported by libleanrt, not declared in lean.h) | `caml_e4_thread_init` / `caml_e4_thread_finalize` | `thread_init` / `thread_finalize` (each worker domain) |
| — | `caml_e4_release`, `caml_e4_is_released` | `release : t -> unit` (idempotent), `is_released` |

Decisions (`E4_bridge.decision`, `to_wire` / `of_wire`, the grammar `Bridge.parseDecision`
accepts): `Evaluate` = `evaluate`; `Flush` = `flush`; `Fire o` = `fire:<o>`;
`Evaluate_fiber f` = `evaluate:<f>`; `Answer {fiber; token; value}` =
`answer:<fiber>:<token>:<nat>` — `RunDecision.answerAsync`, the cross-machine message:
it resumes a fiber parked on that token with `Prim.success (Val.nat value)`. Natural
numbers are digits only, as Lean's `String.toNat?`. A string the Lean side does not parse
is applied as the identity (C5), which is why `to_wire` is the only producer.

Programs in the table: `p42`, `pBind`, `pFork` (fork a child that yields then succeeds
with 7, await it), `pTwo` (two children, awaited in order), `pAwait` (park the root on a
fresh Deferred; only an external `answer` resumes it).

## The bytes path

A program also crosses as its canonical bytes (`Effect4.Program.Wire`, framing `tag ::
be64 length :: payload`), hex-encoded: `program_hex p` is the bytes of a table program,
`load_hex ~hex` decodes them exactly, type-checks the result and loads a machine from it —
so the machine that runs is the program the bytes name, or none.

Lean's `e4_load_hex` is total: it answers a `Session` for every string, named `bytes` when
the bytes were accepted and `!refused:decode` / `!refused:ill-typed` when they were not,
and a refused session carries `p42`'s machine. Handing that out would silently run `p42`
in place of the bytes asked for, so `E4_bridge.load_hex` reads the name, releases a refused
session and answers `Error Decode` / `Error Ill_typed` (`type refusal = Decode | Ill_typed
| Other of string`, `pp_refusal`); `Ok` is the only way a session escapes. `name` is the
loaded program's name and survives `step` and `drive`.

## The memory rule

Lean objects are reference counted and single-threaded. A machine's Lean value is
created, stepped and released on its owning domain and never leaves it: the session is
reachable only from the worker's private table; `Inspect` answers with parsed strings and
ints; the old value is released on the owner right after the step that replaced it; at
shutdown the worker releases everything it still owns and finalizes its Lean thread
state. Only strings and ints cross domains: decisions in (mailbox), event rows, fiber
lines and status records out (ring, reply). No `lean_mark_mt`, no shared Lean heap. The
OCaml custom block holding a `lean_object*` is domain-local too; its finalizer is a no-op
once the block was released (C2).

## Not in this build

Checkpoint, store writer and migration (§4 of the architecture note) are not here; the
ring is in-memory only; there is no wire (sessions) — the drivers are the callers. A
host-level test of the `Full` refusal is not deterministic without a way to hold a worker
still, so M2 is tested at the mailbox and `Full` is only exercised through the API type.
The `.sexp` files carry this machine's absolute paths and are regenerated, not shared.
