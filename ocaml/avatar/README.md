# The avatar — the Machine as OCaml 5 effect handlers

`ocaml/avatar/` is the largest piece of the OCaml estate: `src/Effect4/Machine/*.lean` — the
Lean model of the Effect runtime, called `src/Effect4/Machine/*.lean` until "Prod cleanup 3" —
transcribed into OCaml 5, one OCaml module per Lean file, every carrier keeping the Lean
name, the Lean field order and the Lean arm order.

It is **route (b) of the fidelity ladder** (`docs/research/2026-09-04-ocaml-estate-and-parity.md`
§4f): an effects-native OCaml runtime, not a one-for-one image of the Lean model. The reason
is one design decision, `DIVERGENCE 1` in `deep_fibers.ml:8-15`: Lean's `FrameFiber` holds
the continuation as data (`current : Prim`, `stack : List Prim`), the avatar holds it as the
OCaml stack — an unstarted fiber is a closure, a running one is `Onstack`, a parked one is a
captured one-shot continuation. That is what makes the avatar fast and native, and it is why
it can never be one-for-one. Route (a), the same Lean model running as generated code, is
`ocaml/gen/` (LCNF → OCaml) and `ocaml/link/` (compiled Lean linked in).

**The Lean machine is the authority.** Where the two disagree, the avatar is wrong. The
avatar's job is to be a fast, honest, checkable executable of the model, and to state every
place it departs from it.

## 1. Layout

The library (`dune`, `(library (name effect4_avatar) (public_name effect4-avatar))`) is
fifteen modules; the two executables are thin drivers over it.

| module | what |
| --- | --- |
| `deep_fibers.ml` | `Machine/Fibers.lean`: the fiber machine — `Prim`, `RunFiber`, `RunMachine`, the dispatcher, the `WithFiberAction` arms, `drive`, `evaluatePrim`, `settle`, `exitFiber`, `fireObserver`, `countdownPark`, `interruptRecord`. The divergence table is its header (§4). |
| `deep_stores.ml` | `Machine/Stores.lean`: the three S2 stores (`ref`, `deferred`, `scope`) and the `RunInterp` over them; `sync_op_step` is `syncOpStep` arm for arm. Carriers generated (§3). |
| `deep_context.ml` | `Machine/Context.lean`: the first-order environment (`Requirement`, `Service`, `Context`), the value alphabet `Val`, the well-known keys and references, the four hooks `Fibers` reads off `χ`, `ContextUpdate`. Carriers generated. |
| `deep_layer.ml` | `Machine/Layer.lean`: the memo world, the Layer scope and Deferred stores, the value helpers and the store step under `Prim.sync`. Carriers generated. |
| `deep_forkflow.ml` | the fiber profile's alphabet — twelve `FiberOp` rows, the value codings of the profile's requests and answers, the refusal alphabet. **Avatar-only**: its Lean carriers (`git:c407ab7:Effect4/Deep/ForkFlow.lean`) were archived and have no home under `src/Effect4/Machine/`. Carriers generated, against a description that outlives the Lean file. |
| `deep_census.ml` | GENERATED by `extract-census.py` from `Test/Audit/RuntimeCoverage.lean`: one record per census row that names a Machine witness, in the Lean row order. The join `deep_clauses.ml` and `deep_witnesses.ml` read back. |
| `deep_clauses.ml` | `Machine/Clauses.lean`: one OCaml entry per Lean theorem, in the Lean order, each with the line it ports and the census rows it is tagged with. |
| `deep_witnesses.ml` | `Machine/Witnesses.lean`: the executable witnesses — each runs the machine(s) its theorem reads through the avatar (`replay` over an explicit decision tape, as `replayEval` does) and states the theorem at the avatar's alphabet. |
| `fibers_fixture.ml` | the `fiber` family, transcribed from `git:606918eb73daefcc235a261fce879bf910f2471e:harness/trace/fibers-fixture.stub.ts`: nine bodies keyed by the numeric code a golden's `op fork <code>` row carries. |
| `store_fixtures.ml` | the `ref`, `deferred`, `scope` and `layer` families, transcribed from the harness fixtures; each program is the same sequence of service calls the TypeScript makes. |
| `extra_fixture.ml` | the `extra` family: witnesses for `WithFiberAction` arms no committed golden reaches (`awaitAllFailFast`, `snapshotAwaitNewChildren`, `refusesUnimplementedArm`, …); the reference is rc.112 via `extra_rc112.mjs`, and the avatar-only ones say why. |
| `corpus_dsl.ml` | the adversarial corpus as data: a program is a list of steps over the union of the five service alphabets plus a root table for the bodies its forks name. |
| `corpus_data.ml` | GENERATED by `dune` from `corpus/programs.txt` (compiled in, because under js_of_ocaml there is no file to open). |
| `corpus_run.ml` | the avatar's interpreter for that DSL. `corpus_rc112.mjs` interprets the same text over `effect@4.0.0-rc.112`, so neither face can drift from the other by transcription. |
| `avatar_trace.ml` | the wire form of the shared trace alphabet, matched against `git:c407ab7:harness/trace/tracer.ts`: unit is `[]`, a list is right-nested pairs closed by unit, a handle is its index in first-seen order. |

Executables:

- `avatar_main.ml` — one program, one tape, one TSV on stdout. Reads `EFFECT4_FAMILY`,
  `EFFECT4_PROGRAM`, `EFFECT4_TAPE`, `EFFECT4_RULES`, `EFFECT4_PIN`, `EFFECT4_SHA`;
  `EFFECT4_EVENTS=1` appends the machine's own `RunEvent` trace, `#`-commented.
- `avatar_witnesses.ml` — the witness and clause report: every witness of `deep_witnesses.ml`
  under the clause probe, every clause of `deep_clauses.ml` it exercises, one deterministic
  report whose bytes are the same on all three hosts.

Not in the library: `jsprobe.ml` (the JS-boundary probe, its own runtime),
`fuzz_register.ml` (links P5's generated corpus fixture, copied in by `run-fuzz.sh`).

## 2. Build and run

The build is dune's, from the estate's workspace root `ocaml/` (`ocaml/dune` lists
`avatar server gen`). On this machine (Windows 11) OCaml runs in WSL Ubuntu, in the
`effect4` opam switch (OCaml 5.1.1, dune 3.24.2, js_of_ocaml 5.7.1); **node is not on the
WSL PATH**, so the js_of_ocaml host runs under the Windows `node` from PowerShell, or under
`node.exe` through WSL interop.

```
wsl -e bash -lc 'eval $(opam env --switch=effect4 --set-switch) &&
  cd /mnt/c/Users/kokok/Dev/lean4-effect4/ocaml && dune build avatar'
```

That produces, in `ocaml/_build/default/avatar/`, both executables in all three modes:
`avatar_main.{bc,exe,bc.js}` and `avatar_witnesses.{bc,exe,bc.js}` (the `.bc.js` under
`--enable effects --target-env=nodejs`, the modelled backend). `build-dune.sh` builds the
same thing out of tree with `--root .`; the superseded shell builder has been retired.

### The witnesses, on three hosts

```
# native and bytecode, in WSL
./_build/default/avatar/avatar_witnesses.exe > native.tsv
ocamlrun ./_build/default/avatar/avatar_witnesses.bc > byte.tsv
# js_of_ocaml, under the Windows node, from PowerShell
node C:\...\ocaml\_build\default\avatar\avatar_witnesses.bc.js > jsoo.tsv
```

or `run-witnesses.sh`, which does all three (finding `node`, else `node.exe` via interop),
requires them byte-identical, writes `out/witnesses.report.tsv`, and then runs the count,
census, park-guard and pin gates of §5.

### The corpus, on three hosts

```
wsl -e bash tools/run-corpus-wsl.sh <outdir>      # native + bytecode, 158 programs each
pwsh tools/run-corpus-jsoo.ps1 <outdir>           # the js host, under the Windows node
wsl -e bash tools/compare-faces.sh <outdir>/native <outdir>/byte
wsl -e bash tools/compare-faces.sh <outdir>/native <outdir>/jsoo
wsl -e bash tools/compare-faces.sh <outdir>/native out/corpus .tsv .ocaml.tsv
```

Both runners prefer the workspace build (`ocaml/_build/default/avatar/`) and fall back to a
project-local `--root .` build; `AVATAR_BIN` overrides. `compare-faces.sh` compares the
event rows only — the header rows carry each run's own digests and pin.
`tools/run-corpus-rc112.ps1` produces the rc.112 reference face over the vendored package,
and `compare.py` compares under the mask table.

A single program, by hand:

```
EFFECT4_FAMILY=extra EFFECT4_PROGRAM=awaitAllFailFast EFFECT4_TAPE=0:0,1:0 \
  EFFECT4_EVENTS=1 EFFECT4_STATUS=1 ./_build/default/avatar/avatar_main.exe
```

## 3. The generated half

Four modules carry a block of **generated carriers**, between
``(* Generated by OCaml5.Ml (`Render.lean`, seat W1). Do not edit; edit the descriptions.``
and `(* ===== END GENERATED =====`:
`deep_stores.ml`, `deep_layer.ml`, `deep_context.ml`, `deep_forkflow.ml`. They are rendered
from hand-written descriptions of the Lean carriers:

| file | what it is |
| --- | --- |
| `src/OCaml5/Avatar/Part.lean` | the descriptions (`Deep.Stores.deferredCell`, `Avatar.cmd`, `Avatar.runEvent`, `Avatar.withFiberAction`, …), the type substitution table, and `#guard`s pinning arm counts and rendered names |
| `src/OCaml5/Tools/RenderDeep.lean` | the driver: `lean --run … RenderDeep.lean stores\|layer\|context\|forkflow` prints the block |
| `render-deep.sh` | runs the driver and diffs the block against the real file (`--write` rewrites it) |
| `src/OCaml5/Avatar/Check.lean` | the **projection guard**: the hand description projected against the Lean declaration it describes, row by row |

There is no `fibers` mode: `deep_fibers.ml` carries no generated block (its descriptions are
diffed by `ocaml/tools/fuzz.sh avatar`).

The projection guard stood at **48 / 58 agree** at the last recorded run
(`tools/derivedcheck-after.txt`, 2026-09-04). The ten remaining `DIFF` rows are listed in §7.

## 4. The divergences

Four, each stated in `deep_fibers.ml:1-56` and covered by the descriptions rather than
absorbed by them.

| | where | what it means |
| --- | --- | --- |
| **1** the frame pair | `deep_fibers.ml:8-15` | `RunFiber.frame`'s `current : Prim` and `stack : List Prim` become the OCaml stack: unstarted = a closure, running = `Onstack`, parked = a captured one-shot continuation, interrupted-before-start = `Failing cause`. The other three `FrameFiber` fields are literal. **The one field pair whose simulation relation is not an equality** — and the reason the machine cannot be inspected from OCaml (`§4g` of the estate note: OCaml 5 continuations are opaque). |
| **2** `Cmd` has 8 arms, `cmd` has 5 | `deep_fibers.ml:17-47` | `evaluate`, `resume`, `launch race`, `link …`, `drainDue` map arity for arity to `Cevaluate`, `Cresume`, `Claunch`, `Clink`, `CdrainDue`. `loop` has no OCaml existence (`continue k` runs the fiber to its next `perform`; the `yielding` latch is a fiber field; the iteration prelude is `guard`/`resume_iteration`, so the op counter counts performs, not `Prim` nodes). `deliver` and `finish` are **functions**, not commands — a `Cdeliver`/`Cfinish` value would have no construction site. `Avatar.cmd` in `Render.lean` still lists all eight, the three absent ones carrying a comment that says so. |
| **3** in place | `deep_fibers.ml:49-51` | Lean threads the machine through pure updates (`RunMachine.update`, `modify`, `emit`); the OCaml record has `mutable` fields, so `update` and `modify` are the identity. A consequence: `finish` reads the live record, which is what Lean's re-read of the fiber sees. |
| **4** nested commands | `deep_fibers.ml:53-56` | Lean's `drive` returns the commands a step owes and runs them before the rest of the list; the OCaml arms run them inline, at the same point in the order, because `retc`/`exnc` execute on the resumed stack rather than inside the `match_with` that installed them. Also why drive fuel is not a monotone step counter (`server/README.md` R2). |

One recorded residue, not a divergence: `Completion.ofRefGet` is a `sync` program that
cannot be performed from an awaiting arm, so `completion_prim`'s `ofRefGet` arm refuses by
name when run; `deferred.complete-with-stores-effect` stays a Lean-only clause
(`tools/drift-report.md`, "Residue").

## 5. What the avatar holds itself to

| | property | how |
| --- | --- | --- |
| **A** | The witness report is **byte-identical on bytecode, native and js_of_ocaml.** A host that disagrees is a bug in the avatar or in a host, and the report says which rows moved. | tested every run (`run-witnesses.sh`, `cmp`) |
| **B** | **Witness identities.** One `deep_witnesses.ml` entry per `Machine/Witnesses.lean` theorem and one `deep_clauses.ml` entry per `Machine/Clauses.lean` theorem; exact names and counts are gated against the Lean files. | tested (`run-witnesses.sh`, `check-witness-names.py`) |
| **C** | Every portable clause and witness probe returns `HOLDS`; a `FAILS` row refuses the gate. Portability refusals remain explicit report rows. | tested |
| **D** | The **park guard** (seat F2's one-shot probe) is silent on every run: no continuation is resumed twice, no park is left dangling. | tested (`park-guard violations 0`) |
| **E** | **Corpus = rc.112.** Every corpus program the reference can spell produces the same rows under every mask. 149 of the 158 have an rc.112 surface (5 have none for `childrenSnapshot`, 4 budget programs do not terminate under the 8 s deadline). | tested (`compare.py` against `tools/run-corpus-rc112.ps1`'s face) |
| **F** | **The corpus is host-invariant**: 158/158 identical on the three hosts, and identical to the committed faces in `out/corpus/`. | tested (`tools/compare-faces.sh`) |
| **G** | The **carriers are generated**, not hand-kept: the four generated blocks are byte-identical to what `Render.lean` renders, and the projection guard checks the descriptions against the Lean declarations. | tested (`render-deep.sh`, `DerivedCheck.lean`) |
| **H** | The **Lean files are pinned** by content hash (`deep-pins.tsv`, `pin-deep.sh`): a re-spelled arm under an unchanged theorem count is invisible to a count gate, a digest catches it. | tested; reviewed pins and archived inputs are recorded in §7 |
