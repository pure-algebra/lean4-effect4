# The OCaml estate

OCaml is the primary host of the Effect model (ruling of 2026-09-04, `docs/research/
2026-09-04-ocaml-estate-and-parity.md`). This directory is one dune workspace holding every
OCaml program of the estate; its Lean half is the lake library `OCaml5` under `src/OCaml5/`
(root module `src/OCaml5.lean`). Nothing here is a spike any more: each project is a library
with thin drivers, one component per file with a property list at its head, generated files
marked and regenerable, and a report behind every number (`STANDARDS.md`).

One runtime: **the visible machine**, the Lean `RunMachine` itself, running in OCaml. Route 1
(`link/`) holds the compiled Lean machine as an opaque value and steps it; route 2 (`gen/`)
is Lean's own compiler IR translated into typed OCaml, and `engine/` is the host engine
under that generated machine (`docs/research/2026-09-08-engine-brief.md`). Every fiber,
frame, park token, pending resume and event is a field of one value, so it can be inspected,
serialised, moved between domains and messaged through the model's own decision alphabet.
Fidelity is the compiler's. `eff/` is the Lean program IR `Eff` as an OCaml language, so
OCaml can author programs the Lean machine decodes exactly.

The second runtime that once stood beside it, the avatar (the same machine as OCaml 5
effect handlers, `avatar/`), the daemon `effect4d` that served it (`server/`) and its wasm
host (`wasm/`), are archived on the local branch `archive/ocaml5-avatar` at `14e6835`
(engine brief ruling: one OCaml engine, `gen/`). The host over the engine that replaces the
daemon is owed by the host-rows slice.

## The fidelity ladder

Highest fidelity first (`2026-09-04-ocaml-estate-and-parity.md` §4f):

1. compiled Lean linked into the OCaml process — `link/` (native only; the boundary is
   `e4_stubs.c`, a stated trust boundary, not model code);
2. Lean's compiler IR translated to OCaml — `gen/` and `engine/` (typed, value-threaded,
   no handlers; fidelity = the compiler's minus a small rule table).

The two lower rungs, a syntax-level transpiler and a hand port with descriptions and an
overlay, were the avatar's and are archived with it.

## Building

The switch is `opam switch effect4`: OCaml 5.1.1, dune 3.24, js_of_ocaml 5.7.1 pinned (the
modelled backend), the Jane Street v0.16 set. On the PC the switch lives in WSL Ubuntu and
every command below runs there:

```bash
eval $(opam env --switch=effect4 --set-switch)
cd /mnt/c/Users/kokok/Dev/lean4-effect4/ocaml
dune build            # gen, eff, engine
dune test eff gen     # engine's tests are the declared-red sweep row until Phase 1
```

`link/` is built by `link/tools/build.sh`, which first compiles `src/OCaml5/Bridge.lean`
against a Linux `lake build Effect4:static` tree and generates the per-machine link flags
(`link/c_flags.sexp`, `link/lean_flags.sexp`, ignored by git). The Lean half is
`lake build OCaml5` from the repository root.

## Owed

* `gen/` and `engine/`: the Phase 1 regeneration from the current machine (the timer, `advance`,
  the wake protocol) and the prelude repair (`docs/research/2026-09-08-one-generator-plan-v2.md`);
  then the carrier vocabulary that retires the prelude's hand bodies;
* `engine/`: the host over the engine that answers parks (the host-rows slice), which is what
  replaces the archived daemon;
* `link/`: checkpoint, store writer and migration (architecture note §4 rows 5–7);
* `eff/`: the two theorems its report states (erase ⇒ `wellTyped`; encode/decode exactness);
* the OCaml hosts as the third column of `harness/truth`.
