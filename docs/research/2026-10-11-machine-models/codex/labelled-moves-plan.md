# Labelled frame words

Placement: reactive-scheduling and scope-lifetime-finalization, R11.
The proposed `evaluation-moves` structure claim keeps `iteration_moves` as its existing projection.
The stronger classifier records a word and its exact emitted trace suffix.
Consumers are the shared ledger's iteration debit and the source-dependent code weights.

The existing frame relation describes shape only.
Refine its word with labels for each actual move.
An answer label retains its input code and replacement code.
A step label retains its actual events; a pop retains its demand, cause, popped frames, answer, and hook events.
The classification proves that the labels concatenate to the actual trace suffix.
An administrative identity move records events that leave the frame unchanged.

Keep each old shape theorem as a projection of the stronger classifier.
Replace the evaluator census in `Footprint.lean`; do not add another pass beside it.
Keep guard consumers and their statements.
Prove balance once by induction over the labelled word.
Use natural-number inequalities without truncated subtraction.

This structure does not prove that an arbitrary replacement has an admitted source.
A weight instance still supplies its local bound, including any source and state premises.
It establishes no progress, command closure, host agreement, or completed scenario history.

Probe the word, erasure, and balance before replacing the single classifier.
Build its existing guard consumers and audit the changed modules before committing.


A selected finalizer transfers its saved credit to a program start within one evaluation.
Keep that actual pop and replacement in one labelled operation.
Its erasure consists of the old pop and answer moves.
Splitting them would discard the selected credit before the start charges it.
The operation records the actual selected frame, delivered exit, and emitted start.
A replacement without a program start uses the same operation with no start label.

Answer, push, and identity labels admit only administrative events.
Those events contain no frame event or finalizer program start.
This restriction lets a saved-stack ledger prove its local bound without arbitrary event premises.
Current-code weights still require source contracts; input and output code alone do not certify their admission.

Finishing criteria for this slice: one strengthened Footprint census, exact trace concatenation,
old interfaces as projections, a checked ledger consumer, and a narrow audit.
