# The store seam: one command language over a durable prefix, and an exact image

Lean's model gains a durable prefix and a command language. The OCaml disk store serves the same generated commands. Refinement is byte equality of one generated `Image`. Facts are generated from Lean. Semantics are checked by a differential over event tapes. New core module `src/Effect4/Store/Domain/Durable.lean`:

```lean
structure Durable where
  store   : Store
  durable : Nat                         -- the first `durable` nodes are committed
  covered : durable ≤ store.nodes.length
inductive Cmd where
  | put (bytes : Bytes) | get (address : Digest) | move (root : Root)
  | commit | verify | closure (ref : AnyRef)
inductive Event where
  | cmd (c : Cmd) | crash (keep : Nat)  -- the environment: a writer killed mid-commit
inductive Answer where
  | put (o : Outcome) (a : Digest) | got (n : Option Node) | moved (version : Nat)
  | committed (durable : Nat) | verified | closure (w : Word) | recovered (durable : Nat)
inductive Refusal where
  | admission (why : Admission) | unverified (why : VerifyError)
def Durable.attempt : Durable → Event → Except Refusal (Durable × Answer)
def Durable.serve (p : Durable) (e : Event) : Durable × Except Refusal Answer :=
  match p.attempt e with
  | .error r => (p, .error r)
  | .ok (q, a) => (q, .ok a)
structure Image where                   -- what a disk shows of itself
  roots   : List Root                   -- the control file, head-first
  records : List (Digest × Bytes)       -- the pack in write order, staged last
  durable : Nat                         -- records the watermark covers
def Durable.image (p : Durable) : Image           -- (address, Node.encode) per node
def Image.abs (i : Image) : Except ImageFault Durable   -- α; undecodable or repeated digest refuses
```

What `attempt` does for each event:
- **`put b`** runs `putBytes`. Its refusals come in one order: first `Node.read`'s (short, version, kind byte, then the payload's tag, frame, trailing), then `putNode`'s (`malformedRef`, `handleInContent`, then `dangling`/`wrongKind` along `Node.checkedEdges`). A fresh node is appended after the durable prefix.
- **`get d`** answers `Store.find`, which sees staged nodes too.
- **`move r`** commits first, then runs `putRoot` with the refusals `badName`, `staleRoot`, `dangling`, `wrongKind`. So a root never names a staged node (this is `E4_cas` deviation D7).
- **`commit`** sets `durable := nodes.length`.
- **`verify`** runs `Store.verify` on the committed part, which is what a reopen reads.
- **`closure r`** runs `Store.closure`.
- **`crash k`** keeps the first `durable + k` nodes, sets `durable` to that count, and leaves the roots unchanged.

`Durable` has a proof field, so OCaml sees it as abstract (rule 1). The design has no dependent function type and no value-indexed family.

The OCaml side is `ocaml/engine/cas/e4_store.mli`. Every `Store.*` type in it is generated by the LCNF lowering:

```ocaml
type capacity = Host_limit of string            (* a frame or be64 field >= 2^62, M9 *)
type fault =                                     (* damage; no command produces one *)
  | Corrupt of Addr.t | Undecodable of Addr.t
  | Unadmitted_tail of { seg : int; off : int; why : Store.Admission.t }   (* D6 *)
  | Sealed_damage of string | Control of E4_control.open_error
type refusal = Model of Store.Refusal.t | Capacity of capacity | Fault of fault
module type S = sig
  type t
  val serve : t -> Store.Cmd.t -> t * (Store.Answer.t, refusal) result
  val image : t -> Store.Image.t   (* read from the pack and control file, never the index *)
  val crash : t -> keep:int -> t * (Store.Answer.t, refusal) result      (* harness only *)
end
module Model : S with type t = Store.Durable.t  (* Lean's adapter, lowered; hash extern E4_sha256 *)
module Disk  : S                                (* E4_cas over pack, index, control *)
```

Faults are values, so the `Store_error` and `Bad_pack` exceptions stop crossing the seam.

**The refinement relation.** R(D, P) holds when `Disk.image D = Durable.image P`, byte for byte. By `abs_exact` (§5) this is the same as `Image.abs (Disk.image D) = .ok P`. Take an event with R(D, P), where the disk answers `a` and leaves D′. Exactly one of three clauses applies:
1. **`Capacity`.** The image is unchanged and the model step is not taken. The disk serves a restriction of the model's domain, never an extension of it.
2. **`Fault f`.** The image was damaged. `Corrupt d` corresponds to the model's `put (conflict m) d` with `sha256 m.encode ≠ d`. `Undecodable d` means `Image.abs` has no value for the image.
3. **Otherwise.** R(D′, (P.serve e).1) holds, and `a` equals `(P.serve e).2` wrapped in `Model`.

**Why `Corrupt` and capacity refusals stay outside the model.**
- **`Corrupt`.** Every command keeps `Store.Sound` (`putNode_sound`; Rocq `built_sound`). In an addressed store a conflict is a collision (Rocq `put_conflict_collision`). So on every reachable state the disk's split of `conflict` into `Conflict | Corrupt` decides nothing. Adding `corrupt` to `Outcome` would put a disk fact into the model and reopen the Rocq proofs for nothing.
- **Capacity.** The 2^62 bound is this host's integer width, not the store's meaning.
- **Root names are different.** `E4_control.normalise_name` makes "A" and "a" one root on disk and two in the model. That is a difference of meaning, not of capacity, so M8 moves into Lean as `badName`.

## 3. What the implementation hides, and the one owners

**Behind `Disk`:**
- `E4_pack`: segments, CRC, group commit, sealing.
- `E4_index` and the by-Cid table, which are caches.
- `E4_control`: the roots plane's bytes, the watermark, generation, status and scheme.
- `E4_crc` and `E4_cache`.
- Recovery, the writer lock and the fsync order.

`E4_cas`'s public surface becomes `Disk`'s implementation. Behind `Model` are the list, `findIn` and the durable count.

**Above the seam, as clients:** `E4_checkpoint`, `E4_chunk`, `E4_deps`, `E4_shape`, `E4_subterm`, and the host of states. `E4_wal` is not behind this seam: it is a job's journal spine, and a tape enters the store as a `put` of a `tape` node.

## 4. Adapters and agreement

| Adapter | What varies | Category |
| --- | --- | --- |
| `Model` (`Durable.serve`, also lowered into OCaml) | nothing beyond the model | in-process |
| `Disk` (`E4_cas` and its files) | durability, crash recovery, capacity, damage, speed (its one-pass admission scan) | local-substitutable (tests substitute `Model`) |

Agreement is checked in three layers:
- **Byte grammars.** The goldens A1, G1 and G5 stay. A byte language is checked by a corpus that carries Lean's verdicts.
- **Facts.** These are generated: tables, vocabularies, `Admission.ofRead`, `genesisAddress`. There is nothing to compare.
- **Semantics.** A qcheck-stm `Spec` (tooling design §3.10.8) runs every tape through both adapters:
  - `init_state` is the empty `Durable` and `next_state` is `Durable.serve`.
  - `postcond` checks clauses 1 to 3 and image equality after every event.
  - The generator produces nodes that fail two tests at once (L-CAS-4's order), stale versions, crashes at every k, and forge events.
  - G2, G3, G6 and G7 are re-cut as tapes recorded from the model.
  - `rocq/StoreCode.v` prints the same Lean declarations the oracle lowers, so `rocq/StoreLaws.v` holds of the oracle's code.

**How the host of states (§3.5) uses the seam:**
- **Publication.** `Tool.serve` computes the next state purely. The host then puts the entry node (kind 7, naming its action and, by a `ref` edge, its parent entry), and moves the document root at version revision + 1.
- **Stale work.** A `staleRoot` refusal discards the computed state and becomes the request's refusal. The staged entry is harmless because the store only grows. The root version is the revision counter that cancels stale work.
- **Snapshots.** A root plus its `closure` is the unit of transfer. Loading applies the word (`Word.apply`) and rebuilds `Doc`'s proof field by replay.
- **Phase caches.** The decode, check, build and run caches key by the addresses `put` returns.
- **Open.** Recovery leaves a prefix, `verify` runs once, and each document root's entry chain is replayed.

**Where Incremental plugs in.** A cache of `get` by address never needs invalidation (Rocq `put_bytes_never_change`). C6's action cache can be added later as new `Cmd` constructors plus a second map in `Store`, without changing any existing answer.

## 5. Laws

1. `serve_refused`: a refused event leaves `Durable` unchanged (the probe's `refusal_inert`, `review-probes/CoreSketches.lean`).
2. `serve_grows`: no command removes or replaces a node (`putNode_sub`, `putRoot_nodes`; Rocq `put_grows`, `put_bytes_never_change`).
3. `serve_get`: after a fresh or duplicate put, `get` answers the node (`putNode_find`; Rocq `put_get`).
4. `serve_conflict`: a conflict changes nothing and shows the occupant; in an addressed store it is a collision (`put_conflict`; Rocq `put_conflict_collision`).
5. `serve_sound`: every command keeps `Store.Sound` (`putNode_sound`; Rocq `put_sound`).
6. `read_ok_iff`: `Node.read b = .ok n ↔ Node.decode b = some n`, and `putBytes` is `putNode` after it (from `Node.decode_exact`).
7. `crash_prefix`: a crash keeps every committed node and a prefix of the staged ones (new).
8. `crash_closed`: the kept prefix of a built store is closed (new, from Rocq `built_ranked`).
9. `roots_durable`: every root names a committed node (new).
10. `abs_exact`: `(Durable.image p).abs = .ok p`, and `i.abs = .ok p → i = Durable.image p` (new, from `Node.decode_encode`, `Node.decode_exact`).
11. `verify_sound` (Lean and Rocq): a store that verifies is sound.
12. `closure_wf`, `closure_closed`: closure is the transfer unit (with Rocq `built_closure_premises`).
13. `putNode_handle`: a node of a content kind that carries a handle is refused (new, M2).
14. Conformance: the disk refines `Durable.serve` under clauses 1 to 3. This is checked by the differential, not proved.

## 6. Trade-offs

**Where leverage is high:**
- Every fact the two sides duplicated becomes generated code, so drift between them becomes a compile error.
- Checking state agreement costs one byte comparison per event.
- The Rocq laws are proved of the oracle's own code.

**Where it is thin:**
- The disk keeps its hand-written admission for its one-pass scan (`check_pure`), so the admission order agrees by test, not by construction.
- Routing the disk's decisions through the lowered `putNode` would make it agree by construction, at the cost of a `Val` tree per put. That should be measured first.

**What this design makes hard later:**
- The interface is synchronous with one writer. An owned remote store, or two writers, needs asynchronous answers and a different crash model.
- `Admission` grows three constructors. `StoreCode.v` has to be re-printed, and the Rocq proofs that split `putNode` gain cases.
- Reserving root bytes 5 and 6 holds back `E4_checkpoint`'s CP3 and `pin` until their consumers land.
- The crash model assumes that a torn write keeps a prefix and that a rename is atomic. The best-effort directory fsync (`E4_control` D7) falls outside it.
