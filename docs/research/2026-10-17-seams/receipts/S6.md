## Departures and proposed decisions

| Correction | Evidence | Proposed decision |
| --- | --- | --- |
| The generator's heartbeat budget counted the whole run, so `Tool.serve`'s closure timed out though each piece lowered alone. | `serve` lowers once each type and each root has its own budget; every existing artefact regenerates and check-ocaml passes. | Budget per item, as Lean budgets per command. |
| The envelope check lived inside `decode`. | `Wire.check` is shared by `decode` and the native shell. | One owner. |
| Requests cross the native boundary as value trees, and the text is the shell's. | `Kit_json` reads and prints by each carrier's generated shape. | Keep the boundary at canonical values. |

## Not done

- **The native exchange over the disk store.** `Exchange.apply` is generated over the Lean store
  model; the native shell needs the chain read and the commit over `E4_cas`, with the generated
  walk, replay and publication. That is the next landing.
- **`Kit_serve` and `E4_host.serve` still serve the kit's own commands** (`check`, `run`,
  `explore`). Their requests are not Tool requests; moving them is a decision about the kit's
  face, recorded here and not made.
- **The JSON number profile.** The Lean driver refuses a natural that binary64 rounds
  (`CodecProfile`); the native reader holds OCaml integers. The fixture has none; a control is
  owed with the exchange.

The semantics report was not regenerated (owner, 2026-10-18).
