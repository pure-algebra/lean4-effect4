# Stage 2 admission audit and byte baseline

**Verdict:** the draft deletes the checked Schema convenience API; it does not silently widen one that survives. The two fixed fixture emitters retain an appropriate finite check through the existing schema-ts gate, provided that gate runs against the retained pre-change generated files. This is not a replacement admission theorem or a general validity claim for arbitrary raw documents. No compiler, generator or repository mutation was performed for this review.

Row 39 (`decisions.md:85`, ontology §3.4:109–143) deletes field admission and keeps the raw Schema printer, Codegen Schema tests, schema-ts, schema-codec, schema-pins and the pinned host. Its original “called by nothing” description is stale: `Codegen/Schema.lean:395–404` does call fieldAdmissible. The agreed closure therefore removes the entire legacy readiness/checked convenience chain and its own tests. It neither substitutes True in documentReady nor recreates the retired checker under another owner. The already-public `moduleSyntax` stays the raw constructor it was (:444–451); its body is unchanged. Existing callers of a deleted checked name will fail to elaborate rather than receive more permissive success from that name. No alias of the old checked names remains in the projected src/Test/tools/harness scan.

The intentional loss must remain explicit in the receipt: the general illegal-name, duplicate-binding, duplicate-reference, duplicate-data-key and persisted-field refusal controls are retired with that API. Host decoding is not an equivalent replacement for all those controls: JavaScript can collapse duplicate keys before fromJson sees them. The raw printer does not claim to retain those refusals, and the two fixture emitters take no runtime input. A new general raw-document caller would need its own explicitly named admission boundary; this patch supplies none. The independent program/type/refusal APIs and Ty.ofSchema checks are unchanged.

## Why the retained fixtures are still checked

- `EmitFixture.lean:8–19` contains a fixed two-property Person document, two fixed associated data objects, and the distinct binding names PersonSchema, PersonSchemaJson, ada and prototypeData. `EmitCoverageFixture.lean:6–8` contains the fixed Coverage.document and the two distinct AllRepresentationsSchema binding names. Stage 2 changes only the outer call from `generate? ... |>.getD ""` to the existing `Render.module house0 (moduleSyntax ...)`; all fixture data stays identical.
- The printer still emits `SchemaRepresentation.fromJson(NameJson)` for both modules (`Codegen/Schema.lean:426–431`). Importing either module in the retained runtime check executes the pinned host decoder; a decoder exception fails the script. The vendored rc.112 functions call decodeDocument/decodeMultiDocument and document this throwing behavior (`SchemaRepresentation.ts:1177–1179,1199–1201`); they do not reconstruct runtime callbacks. The coverage table is fixed by `RepresentationTag.census`, `allRepresentations_tags`, and source-defined `case/<tag>` keys plus StringRef (`SchemaGenerationCoverage.lean:70–84`). Its 22-tag theorem and guard remain.
- `scripts/check-schema-typescript-generation.sh:32–39` emits all three fixtures into a temporary directory and byte-compares them with the retained committed files before any host check. It then requires clean TypeScript compilation (:51–55), six clean Effect-v4 language-service files (:69–79), and successful runtime checks (:82–105).
- The Person runtime check observes the decoded Objects node, two properties, Ada's two raw fields, and an own `__proto__` property. Coverage observes all 22 representation tags in order and both check constructors. The unchanged multi-document fixture calls fromJsonMultiDocument and observes two ordered roots and one shared Number reference. These are finite fixture observations. They do not prove arbitrary Schema validity, a live value decoder/reviver relation, associated-data membership in Person, or compiler equivalence.

No retained fixture byte change is justified by removing the outer convenience call. The previous source string guard is retained as a direct module-rendering guard with the exact same expected string. The raw printer body prefix is text-identical in the prepared projection. Actual emitted equality remains owed to the root's gate run.

**Validation order:** retain the baseline first; after applying stage 2 and its narrow Lean build, run `LEAN_NUM_THREADS=1 bash scripts/check-schema-typescript-generation.sh` before any `make gen-schema-ts` or broad `make gen` that could overwrite expected fixture files. The prescribed derived → lcnf → eff → wire → cas chain does not itself regenerate schema-ts. Do not turn an unexpected fixture difference into a new expected file. If the existing script's checked-in comparators have changed in the meantime, compare all three against the separate baseline below as well.
