# Waiting cleanup and authoring controls

Check an admitted loop that changes a reference, then fails under a scripted host.
Its cleanup reads that reference and waits on another host call.
Read the waiting call's source address and checked reply type from the same recorded run.
Keep production files unchanged.

## Placement

1. **Concept:** host-session-protocol and translation-simulation, the detailed observation of a waiting host program.
2. **Question:** claims `rows-loop-frontier` and `rows-loop-frontier-host`, Q4/Q6b, role simulation.
   These finite controls serve the waiting inspector and the later resource-prefix consumers.
   Address controls also consume `reply-at-call-instance`, role preservation.
3. **Reach:** `LoopedDataRows`, a single fiber, a reference, explicit reply decisions, and an `onExit` cleanup.
   This checks existing cleanup syntax, not `scoped` or `acquireRelease`.
4. **Limits:** finite runs prove no general waiting agreement, progress, resource safety, target execution, or scheduling claim.
   A budget cut stays unfinished and must not start cleanup.
   A source address and a checked reply type establish no safe migration to an edited program.
5. **Unlock:** examples for the waiting inspector, typed reply authoring, and later resource prefixes S1/S2, under R6/R12.
