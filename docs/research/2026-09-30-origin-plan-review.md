The decisions I recommend are:

- **Forks only for this slice.** A birth ledger adds root writers and coverage obligations without demonstrated benefit to the two intended users. In either design, distinguish a nonexistent ID from an existing root when defining lookup.
- **Narrow the architectural rule.** The revised blanket rule that creation facts must never live on records that are updated is stronger than this evidence establishes. The useful local requirement is that ordinary updates cannot alter creation provenance. The ledger meets that requirement here; it need not dictate every future data layout.
- **One operation for the paired write.** `spawn` already has the unique creation site. Give the ledger/event append a small helper if that makes its proof reusable; the helper's extraction alone is not a new guarantee.
- **Keep the paired-append proof.** The retained model proves that appending the same record to both lists leaves their agreement unchanged, including disagreement on malformed inputs. `Keeps` already accepts a proposition-valued observation; no Boolean wrapper is necessary. This is the list law, not a proof of the future `spawn` or complete machine transitions.
- **Write the first statements by hand, then measure.** Trial trace agreement and memo validity, including the hard hook case. Build the command only if repeated statements and successful search justify it. If built, publishing checked theorems is acceptable: `ProofGraph.addTheorem` already checks the proposition and proof's dependencies and checks the declaration in Lean's kernel (`tools/ProofGraph/Search.lean:128–141`). Printing proof text is a review preference, not an identified trust repair.
- **Keep the diagnostic agreement obligation.** It is already an adopted requirement. The new representation can reduce its proof cost without cancelling it.

The revised order should be: freeze the ledger and lookup statements; test hand proofs and the outer-operation premises; add the shadow ledger and the new comparison runner; move readers and proofs; remove the field and regenerate before integration; finish trace agreement and memo validity; only then decide whether to automate the repeated work. M6's statement amendment and any broader proof architecture remain a separate task.
