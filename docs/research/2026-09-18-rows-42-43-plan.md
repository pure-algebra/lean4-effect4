# Rows 42 and 43: polymorphic `Ref`/`Deferred` and function-taking rows (plan, 2026-09-18)

Ruled by the owner 2026-09-18: do both; the language stays a first-order stored program, the
power stays in the builders, the rows and the types widen where Effect's semantics are wanted;
land it with the meta infrastructure. Design authority for the cut: `docs/core/language-cut.md`.

## 1. The design

- **`Ty.refOf (value : Ty)` and `Ty.deferredOf (value error : Ty)`**, dedicated constructors
  as `fiberOf` is. Tried first: `Ty.app (target) (args : List Ty)`; the compiler refused it at
  once, since a `List Ty` argument makes `Ty` a nested inductive, which loses the derived
  decidable equality and every `induction` on `Ty` (three in `Ty.lean` alone). The tree's idiom
  for parametrised handles is one constructor per handle sort, and row 3's `Ty.app` waits for
  the foreign-schema need it was proposed for. `handle t` stays for the argument-less handles.
  `Val.hasTy` at both is what it is at `handle`: coarse by kind (row 44; the world tables type
  the contents). `normalize` normalises the arguments; `sub` is covariant in them pointwise, as
  `fiberOf` is (sound because the checker never writes through a widened handle without
  re-matching the template); `key` gets one code each.
- **`Ty.var (index : Nat)`**: a row template's parameter, never a program's type. `normalize` is
  the identity, `hasTy` is `false`, `render` prints `A`/`E` by index for row declarations.
- **Rows as templates**: `Row.params : Nat := 0`; the thirteen `Ref` rows and the six `Deferred`
  rows use `var 0`/`var 1`. `Ty.instantiate (args : List Ty) : Ty → Ty` substitutes;
  `Ty.matchTemplate (template request : Ty) : Option (List Ty)` binds each variable at its first
  occurrence and checks the rest by `sub`, so the checker's `perform` rule becomes: match the
  request against `row.request`, instantiate `answer` and `error`. A row whose variables the
  request does not fix carries them on the operation: `NativeOp.deferredMake (value error : Ty)`,
  as `Deferred.make<number, number>()` carries them in rc.112 (`E4-CHECK-CE-013`).
- **Function-taking rows by binder terms** (row 43): `NativeOp.refUpdate (f : Term)` and its
  six siblings carry a term evaluated at `env ++ [current]`, typed by the checker at
  `tys ++ [A]` for the request's `Ref<A>`, exactly as `iterate`'s `step` is. `FnName` retires
  from the rows. The store op carries the function as data: `SyncOp.refUpdate (cell) (f : Term)
  (env : List Val)`, and `refStep` evaluates it, so `update` stays one atomic store step (a
  `get`; compute; `set` sequence could be interleaved by a yield). `Term`, `Lit`, `NativeAtom`
  and `evalTerm` therefore move below `Machine` (`Effect4/Store/Term.lean`, namespace unchanged);
  they are first-order data over `Val` and belong with it.
- **Faces**: the printer prints `refOf`/`deferredOf` as `Ref.Ref<A>`/`Deferred.Deferred<A, E>` and a binder term as `(x) => …`; the
  reader reads both (a lambda skeleton in the template table); `typeArgs` on rows is derived
  from the instantiated arguments, not spelled.

## 2. The order, each step built narrowly and committed

1. `Ty.refOf`, `Ty.deferredOf`, `Ty.var`: the compiler lists every non-exhaustive match; the sixteen folded
   traversals (`Program/Folds/Ty.lean`) get their arms and `fold_of` regenerates each connector;
   the `Fold` group regenerates `TyAlgebra` (`make gen-derived`); two wire tags appended
   (`tools/Effect4Gen/wire-tags.json`, stable and append-only); `Ty`'s laws (`key` injective,
   `sub` reflexive and transitive, the join) get the two arms.
2. `Row.params`, `Ty.instantiate`, `Ty.matchTemplate` with their laws (`instantiate` respects
   `sub`; a match is sound: `sub request (instantiate args template)`); the checker's `perform`
   rule; `inv_perform` restated; `CheckSound`; `Progress.answer_typed` per instantiation.
3. `Term` below `Machine`; `SyncOp` ref rows carry `Term × env`; `refStep` evaluates;
   `NativeOp` rows for `Ref`/`Deferred` rewritten (`deferredMake` with its arguments,
   `refUpdate` and siblings with a term); `FnName` retired with its service entries.
4. The straight soundness (`MeaningSound.sound`, `LoopSound.soundB`): the heap column
   `HeapNat` becomes the per-cell table `Ρ` of the typed world, threaded through `TypedAt`,
   with `HandleFit` for cells; the `perform` arms restated once against the template rule.
   This is layer 1's world entering the straight proof, which is why the rows come before S1.
5. Faces: printer, reader, TS profile (`make gen-ts`), OCaml `eff_*` (`make gen-eff`), the
   corpus goldens (`.ty` verdicts change from `handle "Ref.Ref<number>"` to `refOf nat`),
   `check-gen`, `check-host`.

## 2b. Step 2 landed (2026-09-18), and the probe of steps 3–5

The template calculus and the checker's rule, with no row a template yet, so the corpus's
verdicts are unchanged: `Ty.Subst`, `Ty.instantiate`, `Ty.infer`, `Ty.matchTemplate`
(`Ty.lean`, after `sub`); `rowTy` (`Typing/Rules.lean`), which the checker's `perform` arm and
`HasTy.perform` both name, so `inv_perform` (both levels), `CheckSound` and `MeaningSound`
restate against one helper; `Laws/Program/Template.lean` holds the laws, twelve of fourteen by
one `aesop` call each (`infer_closed` is a 400-case split): `closed_members`/`factors`/
`ofMembers`/`normalize`, `instantiate_closed`, `infer_closed`, `matchTemplate_sound`,
`matchTemplate_closed`, `rowTy_closed`, `rowTy_closed_some`, `NativeOp.row_closed`,
`nativeSignature_row_closed`. Three corrections to §1, made by the code:

1. **No `Row.params`.** A row is a function of the operation's data, so `deferredMake (value
   error : Ty)` instantiates its own row as `scopeMake strategy` and `refUpdate f` already do;
   the only variables left are the ones the request fixes. `Row.typeArgs` becomes derived at
   step 5.
2. **Match = infer, then guard.** The law is the guard (`sub request (instantiate σ template)`),
   so inference can only lose completeness, never soundness. A parameter the request leaves
   unbound is `never` — what TypeScript infers for a parameter the arguments do not constrain,
   which happens only on the dead branch a `never` request marks — so there is no new refusal.
   `matchTemplate` takes a seed: step 3's function-taking rows extend the same bindings with
   the term's type (`modify : A → [B, A]` binds `B` from the term), and `rowTy`'s consumers
   do not move.
3. **Variance (decisions row 55).** rc.112 declares `Ref<in out A>` and `Deferred<in out A,
   in out E>`; step 1's `sub` was covariant at both, which step 4's per-cell table would have
   found unsound (widen a `Ref<number>` to `Ref<number | string>` through an `iterate` cursor
   annotation, write a string, read it back at `number` through the first alias). `sub` is
   invariant there now; `fiberOf` stays covariant, as `Fiber<out A, out E>`. The three
   `TypeAlgebra` proofs that enumerate handle arms (`sub_trans_core`, `sub_antisymm_normal`,
   `sub_normalize_of_sub`) each gained the invariant alternatives — the same chore three
   times, so a `sub` induction principle that hides the arm shapes is owed to the bank.

What the probe found for the remaining steps:

- **Step 3, layering.** `refStep` and `syncOpStep` live in `Machine/Stores.lean`, and the four
  cause-query atoms of `NativeAtom.eval` read the cause image (`Val.cause?`, `Stores.lean:430`),
  whose alphabet (`Err`, `Defect`, `Ann`, `causeImage`, `ExitV`, `exitImage`; `Stores.lean:55-562`)
  is in the same module. For a term to be evaluated inside a store step that block moves below
  the stores (`Machine/Alphabets.lean`); then `Term`, `Lit`, `Terms`, `scoped`, `Lit.toVal`,
  `NativeAtom` (the inductive, names, arity, `eval`) and `evalTerm` sit in `Machine/Term.lean`
  in namespace `Effect4.Program` (the name the wire tags, the generator's `Effect4.Program.Term`
  checks and every consumer use), while `NativeAtom.typeOf`/`mono`/`constGeneric` stay in
  `Program/NativeAtom.lean` (they need `Ty`). `refStep` is not parameterised by an
  interpretation: the machine state stays first-order and the step total.
- **Step 3, atoms.** The five `FnName`s as binder terms need `ite : bool → A → A → A` (typed at
  the join), `some : A → option A`, `none : option never` (nullary) and `mul`;
  `zeroWhenPositive = ite (lt 0 a) (some 0) none`, `noChange = none`, `takeAndBump = pair a
  (succ a)`, `double = mul a 2`. Each is one `NativeAtom` row (name, arity, `eval`, `typeOf`)
  and one prelude entry; the language cut §1 gains them.
- **Step 3, rows.** `SyncOp.refUpdate cell (f : Term) (env : List Val)` and six siblings;
  `refStep` evaluates `evalTerm (env ++ [a]) f`, decodes `some`/`none` for the partial rows and
  `list [b, a']` for `modify`; a term that does not evaluate, or decodes to the wrong shape, is
  the step's `none` (a frontier, as a dangling key is). `NativeOp.syncOpOf` takes the
  environment. `Row.fn : Option (Ty × Ty)` (parameter and result templates) and
  `Signature.termOf : Op → Option Term` let `rowTy` type the term at `env ++ [instantiate σ
  param]` and extend σ from its type by the same `matchTemplate`.
- **Step 3, faces.** `Val.hasTy`'s `.handle` arm for `.cell`/`.promise` retires with
  `refTarget`/`deferredTarget` (a cell is only a `refOf`); `LambdaShape`/`atom?`
  (`Codegen/Styles.lean`, `Forms.lean`) become the printing of a binder term `(a) => body` and
  its reading; `nativeServiceTypes` code 7 becomes `refOf nat`; `Test/Program/Gen.lean` and
  `Test/Machine/Fuzz.lean` generate terms instead of names; `Progress.lean`'s `FnName.*_hasTy_nat`
  become the term typing already proved (`evalTerm_hasTy`).
- **Step 4.** `Val.hasTy` is a fold with one coarse handle arm; the per-cell table wants the
  same fold with the arm reading the world. One definition `hasTyWith (oracle : HandleKind →
  Nat → Ty → Bool)`, `hasTy := hasTyWith coarse`, `hasTyIn W := hasTyWith W.oracle`, monotone
  in the oracle, so the existing laws (`hasTy_sub`, `hasTy_normalize`, `hasTy_mono`) generalise
  once and the current ones are instances. `TypedAt` carries `Ρ : List Ty` (allocation order,
  prefix-monotone) beside the stores.
- **Step 5.** `Row.typeArgs` (spelled strings through `parseLegacy`) becomes derived from the
  instantiated answer through `ofNormalized` (`Codegen/Types.lean`); the TS profile and reader
  (`ts/eff/profile.gen.ts`, `read.ts`) must accept `Ref.Ref<A>` generics; there is no
  independent TS checker to mirror (`ts/eff/check.ts` runs the corpus through the profile).

## 3. What the meta estate does for it

The compiler's exhaustiveness check is the arm list; `#traversal_census Effect4.Program.Ty`
names every definition that reads `Ty` and says whether it is still a fold after the arms;
`fold_of` regenerates the sixteen connectors at `[propext]` with no hand proof; the generator
regenerates `TyAlgebra`, the lenses and the `Canonical` instances from the manifest; the
position census is unchanged (`Val` does not change) and the totality gate stays green; the
reader/printer template table takes the lambda skeleton as one row.
