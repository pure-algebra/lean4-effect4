# Rows 42 and 43: polymorphic `Ref`/`Deferred` and function-taking rows (plan, 2026-09-18)

Ruled by the owner 2026-09-18: do both; the language stays a first-order stored program, the
power stays in the builders, the rows and the types widen where Effect's semantics are wanted;
land it with the meta infrastructure. Design authority for the cut: `docs/core/language-cut.md`.

## 1. The design

- **`Ty.app (target : String) (args : List Ty)`**: a parametrised handle. `Ref.Ref<A>` is
  `app "Ref.Ref" [a]`, `Deferred.Deferred<A, E>` is `app "Deferred.Deferred" [a, e]`. `handle t`
  stays for the argument-less handles this wave (row 3's `handle t = app t []` retires it later,
  one move). `Val.hasTy` at `app` is what it is at `handle`: coarse by kind (row 44; the world
  tables type the contents). `normalize` normalises the arguments; `sub` is covariant in the
  arguments pointwise (Effect's `Ref<A>` is invariant at the TypeScript level; covariance here is
  sound because the checker never writes through a widened handle without re-matching the
  template, and it is what `fiberOf` already does); `key` gets one code.
- **`Ty.var (index : Nat)`**: a row template's parameter, never a program's type. `normalize` is
  the identity, `hasTy` is `false`, `render` prints `A`/`E` by index for row declarations.
- **Rows as templates**: `Row.params : Nat := 0`; the thirteen `Ref` rows and the six `Deferred`
  rows use `var 0`/`var 1`. `Ty.instantiate (args : List Ty) : Ty → Ty` substitutes;
  `Ty.matchTemplate (template request : Ty) : Option (List Ty)` binds each variable at its first
  occurrence and checks the rest by `sub`, so the checker's `perform` rule becomes: match the
  request against `row.request`, instantiate `answer` and `error`. A row whose variables the
  request does not fix carries them on the operation: `NativeOp.deferredMake (value error : Ty)`,
  as `Deferred.make<number, number>()` carries them in rc.112 (`E4-CHECK-CE-013`).
- **Function-taking rows by binder terms** (row 43): `NativeOp.refUpdate (f : Term)` and its
  six siblings carry a term evaluated at `env ++ [current]`, typed by the checker at
  `tys ++ [A]` for the request's `Ref<A>`, exactly as `iterate`'s `step` is. `FnName` retires
  from the rows. The store op carries the function as data: `SyncOp.refUpdate (cell) (f : Term)
  (env : List Val)`, and `refStep` evaluates it, so `update` stays one atomic store step (a
  `get`; compute; `set` sequence could be interleaved by a yield). `Term`, `Lit`, `NativeAtom`
  and `evalTerm` therefore move below `Machine` (`Effect4/Store/Term.lean`, namespace unchanged);
  they are first-order data over `Val` and belong with it.
- **Faces**: the printer prints `app` as `Target<args>` and a binder term as `(x) => …`; the
  reader reads both (a lambda skeleton in the template table); `typeArgs` on rows is derived
  from the instantiated arguments, not spelled.

## 2. The order, each step built narrowly and committed

1. `Ty.app`, `Ty.var`: the compiler lists every non-exhaustive match; the sixteen folded
   traversals (`Program/Folds/Ty.lean`) get their arms and `fold_of` regenerates each connector;
   the `Fold` group regenerates `TyAlgebra` (`make gen-derived`); two wire tags appended
   (`tools/Effect4Gen/wire-tags.json`, stable and append-only); `Ty`'s laws (`key` injective,
   `sub` reflexive and transitive, the join) get the two arms.
2. `Row.params`, `Ty.instantiate`, `Ty.matchTemplate` with their laws (`instantiate` respects
   `sub`; a match is sound: `sub request (instantiate args template)`); the checker's `perform`
   rule; `inv_perform` restated; `CheckSound`; `Progress.answer_typed` per instantiation.
3. `Term` below `Machine`; `SyncOp` ref rows carry `Term × env`; `refStep` evaluates;
   `NativeOp` rows for `Ref`/`Deferred` rewritten (`deferredMake` with its arguments,
   `refUpdate` and siblings with a term); `FnName` retired with its service entries.
4. The straight soundness (`MeaningSound.sound`, `LoopSound.soundB`): the heap column
   `HeapNat` becomes the per-cell table `Ρ` of the typed world, threaded through `TypedAt`,
   with `HandleFit` for cells; the `perform` arms restated once against the template rule.
   This is layer 1's world entering the straight proof, which is why the rows come before S1.
5. Faces: printer, reader, TS profile (`make gen-ts`), OCaml `eff_*` (`make gen-eff`), the
   corpus goldens (`.ty` verdicts change from `handle "Ref.Ref<number>"` to `app "Ref.Ref"
   [nat]`), `check-gen`, `check-host`.

## 3. What the meta estate does for it

The compiler's exhaustiveness check is the arm list; `#traversal_census Effect4.Program.Ty`
names every definition that reads `Ty` and says whether it is still a fold after the arms;
`fold_of` regenerates the sixteen connectors at `[propext]` with no hand proof; the generator
regenerates `TyAlgebra`, the lenses and the `Canonical` instances from the manifest; the
position census is unchanged (`Val` does not change) and the totality gate stays green; the
reader/printer template table takes the lambda skeleton as one row.
