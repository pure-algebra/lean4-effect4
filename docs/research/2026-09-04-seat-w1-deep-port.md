## 1. What the port is, mechanically

| | |
| --- | --- |
| one OCaml module per Lean module | `deep_stores.ml` ← `Effect4/Deep/Stores.lean`; `deep_layer.ml` ← `Layer.lean` (checkpoint stub, §5) |
| link order | `deep_fibers.ml`, `deep_stores.ml`, `deep_layer.ml`, … — Lean's import direction (`Stores.lean` imports `Fibers.lean`) |
| carriers | generated by `OCaml5.Ml.Deep.Stores` in `Render.lean`, rendered by `avatar/render-deep.sh`, diffed against the file |
| functions | hand-written, one OCaml declaration per Lean declaration, in the Lean order, each citing its `Stores.lean` line |
| not ported | calls `Deep_fibers.refuse "<Lean name>"`, which raises `Not_ported`; never silent |

### The generator

`Render.lean` gained one delimited section at the end (`SEAT W1` banner) so seat W3's refactor
of `OCaml5.Ml` can re-export the names without merging into it. It adds:

* `Ml.typeName'` — `typeName` with `mangleField`'s keyword escape. `typeName "Val" = "val"`,
  which is an OCaml keyword; the file's own rule (`exit` → `exit_`) gives `val_`. `Ml.typeName`
  does not apply it because no `Fibers.lean` carrier needed it. `#guard`ed.
* `Ml.renameDecl` — renames the single type a `StructDesc.decl`/`InductiveDesc.decl` makes.
  Additive: neither description structure is changed, so W3 sees them as they were.
* `Ml.Deep.Stores` — a 40-entry substitution table, 9 `StructDesc`s, 13 `InductiveDesc`s, four
  tuple aliases, and `generated : List Decl` in dependency order.
* 22 `#guard`s: the constructor count of every `Stores.lean` inductive against the Lean file,
  the field order of every structure, the mangling round-trip on every field name, that no
  description erases an argument (`Stores.lean` is arity for arity, unlike `Fibers.lean`), and
  the exact OCaml names `deep_stores.ml` uses.

`lake build OCaml5.Render` is green. Render and diff with:

```
$ ./workshop/OCaml5/avatar/render-deep.sh stores
…/deep_stores.ml: carriers IDENTICAL to OCaml5.Ml.Deep
```

`render-deep.sh --write` rewrites the block. `render-deep.lean` is the `lake env lean --run`
driver; it lives under `avatar/`, which is not a `srcDir` of any `lean_lib`, so lake never
builds it. `tools/fuzz.sh avatar` still reports the five `Fibers.lean` carriers IDENTICAL.

### One `#guard` is a finding

`ActionName` (`Stores.lean:377`) and `WithFiberAction` (`Fibers.lean:258`) have the **same 17
constructor names in different orders**: `setInterruptible` is `WithFiberAction`'s twelfth and
`ActionName`'s sixteenth. A0 §3 lists no such row. `deep_stores.ml` follows the `Stores.lean`
order, because that is the file it is the port of; the `#guard` pins both facts.

## 3. The divergence table (rows W1-1 … W1-11)

Each row is a place the OCaml differs from the Lean spelling. A0's eight rows still stand and
are not repeated.

| # | Where | Divergence |
| --- | --- | --- |
| **W1-1** | `Val` (`:141`) | Substituted by the avatar's wire alphabet `value` (`deep_fibers.ml:64`). The two are different alphabets, and the map is not injective either way: `Val.fiber`/`.cell`/`.promise`/`.scopeHandle` all become one `Vhandle` under the wire's first-seen handle counter (`handle_index`, `deep_fibers.ml:371`); `Val.exitNil`/`.exitCons` become one `Vlist`; `Val.exitOk`/`.exitErr` become `Vsome`/`Vnone` (see W1-8); `Val.context` has no image (`χ` is `unit`). Conversely the wire's `Vpair`, `Vstring` and `Vsome`/`Vnone` have no Lean arm — they are the *fixture's* shapes (`harness/trace/atoms.ts`). A relation stated on `Val` needs this table as its clause. |
| **W1-2** | `DeferredCell.completion` (`:655`) | Lean stores `Option Program`; the avatar stores `Option Completion`. `Program` is an OCaml closure (DIVERGENCE 1), and the fixture's `poll`/`awaitError` rows read the *exit* back out of the slot, which a closure cannot answer. `completionPrim` is the map Lean applies at store time and the avatar applies at read time; both are declared, so the two spellings are visible. |
| **W1-3** | the harness fixture's alphabet | The `ref`/`deferred`/`scope` families' rows are **not** `SyncOp` arms and cannot be: `Ref.update(r, n => n + a)` is a JavaScript closure over `a`, and `FnName` (`:94`) has five *named* functions and no parameterised one. The fixture's rows run on the same `RefHeap`/`DeferredStore`/`ScopeStore` through the same `refPeek`/`refPoke`/`DeferredStore.*`/`ScopeStore.*` primitives `refStep` and `syncOpStep` are built from, declared as a second family of `store_request` constructors. So `refStep` and `syncOpStep` are ported and *not on the golden path*; they are exercised by `deep_witnesses.ml` (checkpoint 4). |
| **W1-4** | `SyncOp.deferredPoll` (`:224`) | Lean answers `Val.bool slot.isSome`; the fixture's `poll` row answers the completion's exit (`Vnone` / `Vsome (Vpair (bool, value))`). Both are in the file: `sync_op_step` answers the bool, the `Rdef_poll` arm answers the exit. |
| **W1-5** | `Supervision.ForkOptions` | `deep_fibers.ml` carries neither `MaskMode` nor `ForkOptions`: its `spawn` (`:631`) takes `~daemon` and inherits the parent's mask, i.e. `⟨startImmediately := false, maskMode := inherit⟩`. Kept, so those three keep running; it is a defect of the wire decoding, not of the store, and the fix belongs with P5's generator. |
| **W1-7** | `exitsVal` (`:971`) | `exits_val` is `Vlist (map reify_exit_val)`, i.e. a list of `Vsome`/`Vnone`; the machine's own spelling, `resume_prim RexitsValue` (`deep_fibers.ml:568`), drops the `Vsome` wrapper because `WithFiberAction.awaitAll`'s wire row carries the raw values. **The avatar has two meanings for one Lean function.** Not reconciled: the machine's is on the golden path and this one is not, so changing either would be a behaviour change made blind. | **W1-8** | `reasonsOfVal` (`:976`) | Lossy at this alphabet, because `reifyExitVal` mapped every failure to `Vnone`. | **W1-9** | `contAOf`/`contEOf`/`actionOf` | Refuse *structurally*, not for want of writing. Three groups:

1. **Structural** (W1-9): `contAOf`, `contEOf`, `actionOf`. These do not become writable by
   more work; they become writable only by giving the avatar a `Prim` tree, which is the
   thesis A0 rejected.
2. **Needs a fork over a `ProgName`** — `progOf`'s six fork arms, `closeParChain`,
   `finProgram (closeChildScope)`. `deep_fibers.ml`'s `arm_fork` (`:1108`) takes an `int` code
   into the fixture's root table; a `Prim`-alphabet fork needs `spawn m f (prog_of child) ~daemon`
   with a `fork_options` mask. **This is the precise next step for checkpoint 3** and it is
   small: generalise `arm_fork` to take a `(string * value) -> (unit -> value)` pair instead of
   a code, keep the code-taking arm as a wrapper so the golden rows are unchanged, and add
   `Rfork of prog_name * fork_options` to `store_request`.
3. **Needs a machine arm A0 already lists as absent**: `intoDeferred`/`intoBody` (`Prim.exitFrame`),
   `onExitOf` (`Prim.onExit`), `parkThen` (`Prim.async` at an external slot), `Completion.ofRefGet`.

`Effect4.Deep.Layers (unknown store_request)` and `Effect4.Deep.stores (unknown store_request)`
are the chain's tails — an unclaimed request refuses with the module that did not claim it.
