# API design review: the app-level surface by use, and the redesign

Date: 2026-09-04, on `75002d7` + the uncommitted `Effect4/Api.lean`. Source: every public
signature of `Effect4/{Api,Syntax,Schema,Surface,Target,Store,StdLib,Arch,Data,Char}`
(scratch `sigs.txt`, 1,530 lines) and the import graph. Vocabulary: `docs/…/codebase-design`
(module, interface, seam, depth). Decisions at the end, to be ruled one at a time.

## 1. The surface by use

### 1.1 Ingest (outside → Lean data)

| reader | signature today | where |
| --- | --- | --- |
| JSON Schema → representation | `ofJsonSchema : Json → Except Refusal Representation` (fuel 64 inside) | `Surface/JsonSchema.lean` |
| MCP `tools/list` → tools | `ofMcpToolsList (refs) : Json → Except Refusal (List (Tool refs))` | `Surface/Agent/Emit.lean` |
| `wrangler.json` → deployment | `ofWrangler : Json → Except Refusal Deployment` | `Surface/Deploy/Emit.lean` |
| path text → path | `Path.parse? : String → Option Path` | `Surface/Api.lean` |
| TS literal → JSON | `reifyJson? : Expr → Option Json` | `Target/TypeScript/Schema.lean` |
| annotation payload → mark | `SurfaceMark.parse? : Json → Option SurfaceMark` | `Surface/Annotate.lean` |
| spellings → alphabets | `Method.ofSpelling?`, `Host.ofName?`, `Kind.ofName?`, `RepresentationTag.ofTagName`, `UnionMode.ofModeName`, … | everywhere |
| rc.112 exports → census | `Rc112.entries` (generated by `scripts/generate-stdlib-census.ps1`) | `StdLib/Rc112.lean` |
| Effect TS text → `Eff` | `readEff` (A4, not landed) | `Syntax/Read.lean` |

Two failure shapes (`Option` vs `Except Refusal`), five spellings of "read back"
(`of…?`, `parse?`, `ofName?`, `ofSpelling?`, `ofTagName`), readers living in emitter files,
and the round-trip law stated per alphabet (`ofName?_name`) but not for the carriers.

### 1.2 Model and check (the carriers)

Five Surface carriers, twelve types, one hand-copied shape each:

```
identified / described / nameLegal / … : α → Bool          -- the clause predicates
clauses  : α → List (Bool × Refusal)                        -- the clause list
check    : α → Except Refusal Unit                          -- = Facts.firstRefusal ∘ clauses
WellFormed : α → Prop      wellFormed : α → Bool            -- + Decidable instance
Identified / Described / … : α → Prop                       -- one Prop twin per predicate
json : α → Json            instance : Canonical α := ⟨encode ∘ json⟩
<carrier>Rep : Representation    <carrier>Doc : Document    -- the schema view of the carrier
```

`Entity`, `Domain`, `Endpoint`, `Group`, `Api`, `Tool`, `Resource`, `Prompt`, `McpServer`,
`Deployment`, `Page`, `Site`: 12 × ~15 declarations = the 300 lines of `Surface` that are
the same function twelve times. The interface of a carrier is `clauses` and `json`;
everything else is derivable. Composite carriers (`Api` over `Group` over `Endpoint`)
re-implement the fold (`checkGroups`, `checkEndpoints`, `checkTools`, `checkPages`).

Every carrier that mentions a schema is indexed by `refs : List ReferenceEntry`
(`Tool refs`, `Api refs`, `Sch refs k`), and emitters take `(dom : Domain) (api : Api dom.refs)`.
The index is the right idea (a carrier is only meaningful under its references) but it
appears in ~120 signatures; a `Domain` is already the bundle, and `Sch refs k` (a
representation with a kernel-checked `Kind`) is the good part to keep.

Fixtures live in the library: `shopDomain`, `shopApi`, `shopServer`, `getUserTool`,
`docsDeployment`, `docsSite`, `docsWorkerLines`, … (`Surface/{Entity,Api,Agent,Deploy,Site}.lean`).

Every emitter refuses silently (`none`) for a reason the carrier's `check` would have
named; the "ready" predicates (`emitReady`, `documentReady`, `generationReady`,
`requestReady`) are a second check vocabulary beside `WellFormed`. The rule ledger
(`Surface/Emit.lean`: `Rule.id`, `stance`, `pins`, `receipt`) lists the emitters but is not
attached to them: `Rule.apiHttpApi` and `httpApiModule` know nothing of each other.

### 1.4 Program and run

`Eff Op` with `Signature Op` (`rowOf`, `atomOf`, `scopeKey`) is a clean seam: one instance
(`NativeOp`), `typeOf`, `print`, `compile`, `interpOf`, and `Api` fixes `Op := NativeOp`.
Keep. The one wart: `Syntax.Eff` imports `Target.TypeScript.EffectV4` for `Spelling`
(`Ty.ofSpelling`), so the program layer depends on the codegen layer.

### 1.5 Data plane

`Representation` (22 constructors, each carrying `annotations` and `checks`), `Check`,
`Document = representation × references`, `Annotations = Option (List AnnotationEntry)`,
`AnnotationKey A` with a lawful codec and optics (`Lens`/`Optional`/`Traversal`),
authoring combinators (`string`, `struct`, `property`, `Check.pattern`, …), field admission
(`FieldAdmissible`). Sound design; only the names are flat (`Effect4.Representation`,
`Effect4.Document`, `Effect4.Json`, `Effect4.Lens`). Six modules are prose-only roadmap
stubs (`Codec`, `Value`, `Foreign`, `Registry`, `Getter`, `Transformation`; 1,340 lines,
four with zero declarations).

### 1.6 Store and evidence

`Canonical`/`LawfulCanonical`, `Digest`, `Trie`, `Store`, `Pin`: a real deep module with
laws. `Canonical` instances are written by hand eight times as `⟨encode ∘ json⟩`. `Arch`
(`accepts`, `Json.ofNat`, `toJson?`, the views) is "schema views of the model" and
`Arch.Views` imports `Deep.Layer` for one view, which makes `StdLib.Entry → Arch.Views →
Deep.Layer`: the export census depends on the fiber machine.

### 1.7 Duplicated helpers

`objGet/objSet/objDelete/objKeys/objMerge` (JSON object ops) in `Surface/JsonSchema`;
`optionalString`/`optionalStr` in `Agent` and `Deploy`; `dedupeNames`/`dedupNames`;
`namesUnique`/`statusesUnique`/`keysUnique`/`firstDuplicate`/`firstFailing`; ten `…Fuel`
functions each threading `64` through reference resolution (`spellFuel`, `toJsonSchemaFuel`,
`ofJsonSchemaFuel`, `acceptsShape`, `kindCheck`, `objectProperties?`, `unresolvedReference`,
`closeKeys`, `qualifyEntities`, `rewriteRefs`, `jsonExpr`).

### 1.8 Naming

Read-back: `ofName?`, `ofSpelling?`, `ofTagName`, `ofModeName`, `parse?`, `of…`. Spelling:
`name`, `spelling`, `tagName`, `modeName`, `kindName`. Views: `json`, `view`, `toJson?`,
`persistedJson`. Alphabet lists: `census`, `all`. Files: `Surface/Emit.lean` is the rule
ledger, `Surface/*/Emit.lean` are emitters that also contain readers; `Facts.lean` holds
`Refusal`.

## 2. Typeclasses today

`Canonical α` (bytes), `LawfulCanonical`, `OfVal α` (wire decode, EffectV4), `Decidable
(X.WellFormed x)` per carrier, `Membership` on `Row`. Nothing for "is a carrier", "emits",
"ingests", "has a JSON view".

## 3. The redesign

### 3.1 Layers = namespaces = directories, strict dependency direction

```
Effect4.Data      Json (with object ops), Row, Optic, Float64                — Std only
Effect4.Schema    Payload, Representation, Annotations, Document, Check, Authoring, Keys (the typed annotation keys)
Effect4.Store     Canonical, Digest, Trie, Store, Pin, JsonCanonical (Json.ofNat, toJson?)
Effect4.Surface   Kind (Sch), Refusal, Carrier, Entity, Api, Agent, Deploy, Site   — carriers only
Effect4.Program   Eff, Ty, Typing, Native, Compile (+ Read when A4 lands)
Effect4.Machine   Cause, Exit, FiberId, Supervision, ServiceKey, Frames (Runtime), Scope, Deep.*
Effect4.Codegen   Spell, JsonSchema (out), Schema modules, EffectfulField, Api/Agent/Deploy/Site emitters, EffectV4 profile, Eff printer, OpenAPI
Effect4.Ingest    JsonSchema (in), Mcp, Wrangler, Path, ReifyJson, Census, Read (Eff)
Effect4.Evidence  Views (Arch), StdLib entries and links, Char
Effect4.Api       the facade: Api.Program, Api.Schema, Api.Surface, Api.Codegen, Api.Ingest, Api.Run
```

Arrows point down the list only. `Program` stops importing `EffectV4`: `Spelling` moves to
`Program.Ty` (it is a type language) and `Codegen` maps it back. `Evidence.Views`' layer
view takes `Machine.LayerDesc` (top layer, allowed); `StdLib` stops importing `Views`.

### 3.2 Four classes, in place of twelve copies

```lean
/-- A surface carrier: its clauses and its JSON view. Everything else is derived once. -/
class Carrier (α : Type) where
  kind    : MarkKind
  clauses : Domain → α → List (Bool × Refusal)
  json    : α → Json
  doc     : Document                                   -- the schema of `json`

namespace Carrier
def check [Carrier α] (dom : Domain) (a : α) : Except Refusal Unit := Refusal.first (clauses dom a)
def WellFormed [Carrier α] (dom : Domain) (a : α) : Prop := check dom a = .ok ()
instance [Carrier α] : Decidable (WellFormed dom a) := …
instance [Carrier α] : Canonical α := ⟨encode ∘ json⟩
theorem json_accepted [Carrier α] (a : α) : accepts doc (json a) = true   -- one receipt shape per carrier
end Carrier

/-- A reader from a wire form, with the law that reading a view back gives the value. -/
class Ingest (α : Type) where
  ingest : Domain → Json → Except Refusal α
class LawfulIngest (α) [Carrier α] [Ingest α] : Prop where
  roundTrip : ∀ dom a, WellFormed dom a → ingest dom (json a) = .ok a

/-- An emitter of one artefact from one carrier, tagged with the rule it discharges. -/
class Emit (α : Type) (out : Type) where
  rule : Rule
  emit : Domain → α → Except Refusal out
-- instances: Emit Entity TypeScript.Module, Emit Api TypeScript.Module (httpApi), Emit Api Json (openApi),
--            Emit McpServer TypeScript.Module, Emit Deployment Json (wrangler), …
-- law: Emit.emit dom a = .ok _ ↔ Carrier.check dom a = .ok () ∧ <ready a>, stated per instance
```

Composite carriers get `clauses` by folding their parts (`Api.clauses = own ++ groups.flatMap …`),
which retires `checkGroups`/`checkEndpoints`/`checkTools`/`checkPages`. Emitters answer
`Except Refusal`, never `Option`, and the refusal names the clause; `emitReady` becomes a
clause. The rule ledger is the list of `Emit` instances' `rule` fields, so a rule cannot
exist without its emitter or an emitter without its rule.

### 3.3 References resolved once, fuel gone from the surface

Today every walk over a representation threads `refs` and a fuel of 64 because a
`reference` may cycle. Resolve once: `Domain.resolve : Domain → Except Refusal Resolved`
where `Resolved` carries every representation with references expanded to their entry
(cycles refused at resolution), and every emitter, kind check and JSON Schema walk is
structural on `Resolved`. The fuel parameter leaves every public signature; the eleven
`…Fuel` functions become one.

### 3.4 Naming

Read-back is `parse` (`Except Refusal`) or `parse?` (`Option`) on the type: `Method.parse?`,
`Path.parse?`, `Kind.parse?`. Spelling is `spelling`. Views are `json`. Closed alphabets are
`all`. Files: emitters under `Codegen/`, readers under `Ingest/`, the rule ledger is
`Codegen/Rules.lean`, `Refusal` is `Surface/Refusal.lean`.

### 3.5 Deletions and moves

Delete the six prose stubs under `Schema/`. Move fixtures to `Effect4Test/Fixtures/`.
Move `Arch.Accepts` and `JsonCanonical` into `Schema`/`Store`, `Arch.Views` into
`Evidence`. `Surface.Views`' store of view documents joins `Evidence`.

## 4. Cost

Namespace and directory moves are mechanical but touch every battery. The `Carrier`/`Emit`/
`Ingest` classes replace ~300 lines of copies with ~80 and a receipt shape per carrier; the
per-carrier `Prop` twins (`Identified`, `Described`, …) become theorems about the clause
list. `Resolved` is the one design change with new proofs (resolution refuses cycles;
emitters agree with today's fuel-64 results on every fixture). Machine renames are
separate (3,500 pinned names; snapshot scripts exist).

`Test/` is capitalised on disk because Lean module names are and CI is Linux. Module names
change (`Effect4Test.X` → `Test.X`, `Effect4.Syntax.X` → `Effect4.Program.X`, …); the
machine's *declaration* names (`Effect4.Deep.*`, `Effect4.Prim`, `Effect4.Cause`, …) do not,
so the coverage snapshots and the frame batteries stay valid (D19 is a later step).

   The coordinator converts `Entity`/`Domain` as the template; agents convert the other
