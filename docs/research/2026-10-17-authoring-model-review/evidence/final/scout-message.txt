## A new defect, confirmed at its source

`Typed.emit` (`src/Effect4/Api/Codegen.lean`) prints at `app.rows` only. The `Typed app` certificate, though, comes from `Api.check` (`src/Effect4/Api.lean`) at the full `app.signature`, and `Api.check` never runs signature admission.

So an application can redeclare built-in service code 4 with a `string` carrier:
- the certificate says `string`;
- the emitted module types it as `nat`;
- no error is raised.

The red guard is `rebound` in `probes/A.lean`. Running is safe, because program admission refuses that application (`conflictsBuiltin`).

The scout's fix is a guard: `Typed.emit` refuses any application that declares services or named types. `SigApp.signature_nil` makes that guard exact.

I'd add one design point. The real gap is that "this signature is well formed" and "this program can run" are one check today, `admitSig`.
- Redefining a built-in service is a formation fault, so `Api.check` should refuse it.
- A hole that answers a reference (C9) should still pass `Api.check` and be refused only at `start`. That split between checking and running is what the review asked to keep.

The guard is the cheap fix for slice A. The formation split is a cleaner follow-up, but it changes `Api.lean`, which has many dependents.
