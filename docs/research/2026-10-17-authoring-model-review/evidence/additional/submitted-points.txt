### 1. Confirmed Findings: What the Review Packet Establishes Directly

Every control in [probes.lean](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/evidence/probes.lean) (`C1`–`C10`) and the structural critiques in the review match the live definitions:

1. **De Bruijn levels make closed bytes context-dependent (`C3`):**
   - [`Checker.checkAlg`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Call.lean) and [`Node.childEnv`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Focus.lean) append binder types at the tail of `env` (`env ++ [first.answer]`), and [`argTy`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Call.lean) indexes from the root of `env` (`env[idx]?`).
   - Moving a closed term with internal binders such as `.bind (.succeed (.lit (.nat 7))) (.succeed (.var 0))` under an outer binder changes `.var 0` to read the outer binder unless shifted by [`Eff.weaken`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing.lean) ([`effTy_weaken`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing.lean)), which changes canonical bytes and its CAS digest.
2. **Service provision discharges requirements (`C1`):**
   - [`Checker.checkAlg`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Call.lean) removes provided keys on `.provideService` (`body.requires.erase key`) and `.provideLayer` (`(body.requires.diff layer.out).union layer.req`), falsifying upward requirement inclusion (`requires_graft_mono`).
3. **`Focus` alone is insufficient for local replacement (`C2`, D2/D5):**
   - [`Focus`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Focus.lean) carries only `(program, env, ty)`.
   - [`Sketch.check_fill_focusAt`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Sketch.lean) and [`EditSession.feed`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Edit.lean) require checking the replacement at [`Sketch.sigAt`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Sketch.lean), which threads enclosing definition declarations via [`Eff.partAt`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Parts.lean) on top of `(app.withHoles s.holes).signature`.
4. **Hole admission vs. sketch typing (`C8`, `C9`) and `Tools.Session` signature loss (`C10`):**
   - [`Sketch.hole`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Sketch.lean) compiles hole `k` to `.perform (.external (app.rows.length + k)) (.lit .unit)`. Growing `app.rows` shifts the meaning of existing hole indices (`C8`).
   - [`Sketch.check`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Sketch.lean) runs `Checker.checkModule` without [`admitSig`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/SigApp.lean), so a hole whose answer is a handle (`.refOf .nat`) passes `Sketch.check` (`C9`) even though `admitSig` rejects handle-returning external rows (`rowChecks`).
   - In [`Tools.Session.answer`](file:///Users/pooks/Dev/lean4-effect4/tools/Tools/Session.lean):
     - `"open"` constructs `let app : SigApp := ⟨rows, services, []⟩`, dropping `SigApp.types` (named/recursive types), and [`Tools.Session.appName`](file:///Users/pooks/Dev/lean4-effect4/tools/Tools/Session.lean) hashes only `(app.rows, app.services)`.
     - `"run"` calls `Effect4.Program.admitProgram l.sketch.program (.ofTable rows)`, where [`SigApp.ofTable`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/SigApp.lean) sets `services := []` and `types := []`. Any sketch that uses declared services is admitted in `"open"` and refused in `"run"` (`C10`).
5. **OCaml CAS subterm indexing and checkpoints:**
   - [`E4_subterm.build`](file:///Users/pooks/Dev/lean4-effect4/ocaml/engine/cas/e4_subterm.ml) calls `E4_sha256.digest_sub` over the full encoded byte slice of every visited node (quadratic total bytes hashed in tree depth), and [`E4_subterm.at_prog_path`](file:///Users/pooks/Dev/lean4-effect4/ocaml/engine/cas/e4_subterm.ml) performs a linear array scan (`find_entry`). Furthermore, [`e4_subterm.mli`](file:///Users/pooks/Dev/lean4-effect4/ocaml/engine/cas/e4_subterm.mli) cites `slice_atPath` as proved in Lean, whereas that lemma existed only in the historical scratch note (`docs/research/2026-09-08-cas-repository-algebra.md`), not in `src/Effect4/Laws/`.
   - [`E4_checkpoint`](file:///Users/pooks/Dev/lean4-effect4/ocaml/engine/cas/e4_checkpoint.mli) is marked `PENDING: CAS COMMIT 7`: `machine_image` stores rendered display strings (`mi_exits`, `mi_fiber_rows`, `mi_trace_rows`, `mi_refs`, `mi_store_row`), not a resumable `Fast.t` state, and its node payload hashes `(job, position, tape_prefix, machine_image, prev, engine)`, so commuting histories never collapse to the same checkpoint digest.

### 2. Where the Review Missed or Understated Existing Machinery (Probed in Lean)

Probing the questions against `src/Effect4/` and `tools/` exposed five places where the codebase already answers—or behaves differently from—what the review packet claims. All `#guard`s below were executed via `LEAN_NUM_THREADS=3 lake env lean --stdin` (exit code `0`).

#### Question A: Reference-bearing edits in `SourceSession.feed` vs. the review's `hasReference = false` gate
* **What the review says ([README.md](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/README.md) §4):**
  *"If neither `s` nor `q` contains layer references (`s.hasReference = false` and `q.hasReference = false`), `s.expand = s`, so splice checking via `Sketch.edit` applies directly. If either source contains references, the first version checks the whole candidate source `s'.sourceCheck app`..."*
* **What the code actually does:**
  [`SourceSession.feed`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/SourceSession.lean) (proved coherent in [`SourceSession.feed_coherent`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/SourceTable.lean)) does **not** fall back to whole-program rechecking merely because `s` contains a `LayerTerm.ref`. Instead, it computes `x := s'.expand`, forms `e' := Edit.expanded x e`, and checks whether editing the old expansion at `a` alone produces `x`:
  ```lean
  if (l.expanded.sketch.edit l.app e').map (fun y => (y.program, y.holes)) =
      some (x.program, x.holes) then
    let (ex, d) := l.expanded.feed e'
    (⟨s', ex⟩, d.atSource s'.sites)
  else reopened ()
  ```
* **Executed probe evidence:**
  On `sketchWithRefFrom110To0`, where `[0]` is a layer `.effect svcKeyA (.succeed (.lit (.str "svc-a")))`, `[1, 0]` is a hole, and `[1, 1, 0]` is `.ref [0]` (`sites = [[1, 1, 0]]`):
  - **Editing outside the referenced layer target (`[1, 0]`):** Filling hole `[1, 0]` with `.succeed (.lit (.nat 7))` **splices** (`delta = .spliced [[1, 0]]`), even though the sketch contains `.ref [0]`.
  - **Editing inside the referenced layer target (`[0, 0]`):** Replacing `[0, 0]` with `.succeed (.lit (.str "svc-b"))` (same `EffTy`) splices on `sess.expanded` alone (`(sess.expanded.feed e).2 == .spliced [[0, 0]]`), but because `s'.expand` also updates the copy at `[1, 1, 0, 0]`, `SourceSession.feed` detects the mismatch and returns `delta = .rechecked`.
  - **Implication for `checkReplace`:** Restricting splice checking to `s.hasReference = false` in `checkReplace` would be a **regression** relative to `SourceSession.feed`: any module with a single shared layer reference would lose local splice checking at every unrelated address. The exact condition is the one `SourceSession.feed` already uses (plus checking `s'.program.firstRefFault = none` so a newly introduced forward/cyclic reference to an existing layer is not accepted by the expansion check).

#### Question B: Signature dependency restriction (`SigProgram` and `readsAlg`) already exists in `Effect4.Laws`
* **What the review says ([README.md](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/README.md) §3.2, §3.3; [math.md](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/reviews/math.md) §2):**
  Treats signature dependency restriction as unproved future work (*"Whole-signature keys remain the baseline until dependency restriction is justified"*).
* **What the code already proves:**
  [`src/Effect4/Laws/Program/Signature.lean`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean) **already defines and proves** fold-level dependency restriction over `Eff`:
  - [`readsAlg`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean) is an `EffAlgebra Op (fun _ => Prop)` that collects the exact operations (`eff_perform`), service keys (`eff_service`, `eff_provideService`, `action_context`, `layer_succeed`, `layer_effect`), and definitions (`eff_invoke`) a program reads.
  - [`cata_eff_congr_on`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean) proves that any two algebras satisfying [`EffAlgebra.AgreeOn`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean) on `(okOp, okKey, okDef)` produce identical fold results on any `e` satisfying `cata_eff (readsAlg okOp okKey okDef) e`.
  - [`check_restrict`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean) and [`effTy_restrict`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean) instantiate `cata_eff_congr_on` at `Checker.check.alg` to prove that for any [`SigProgram`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean), `Checker.check s' env p e = Checker.check s env p e` (including refusals) across any [`SigExtends`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Signature.lean).
  - [`src/Effect4/Laws/Program/Sketch.lean`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Sketch.lean) extends this to definition blocks ([`checkModule_restrict`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Sketch.lean)), hole-free programs ([`holes_conservative`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Sketch.lean)), and bounded hole prefixes ([`sketch_reads_its_holes`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Sketch.lean)).
* **What actually remains open for a minimal signature-slice cache key:**
  1. `check_alg_agreeOn` is currently stated for asymmetric `SigExtends s s'` rather than symmetric pointwise agreement on `(okOp, okKey, okDef)` (though `cata_eff_congr_on` itself is already symmetric!).
  2. `SigExtends` requires whole-table equality on named types (`s'.types = s.types`) because [`argTy`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Call.lean) and `Decision.armsIn` read `s.types`, and `readsAlg` does not yet track which `TyDecl` names a term or decision unfolds.

#### Question C: Path independence of `.ok` typing and naturality of refusals
* **What the review says ([execution.md](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/reviews/execution.md) §1):**
  *"The checker fold's carriers include the environment, path, and mode flags. The same source fragment can produce different results at different environments, signatures, paths, or enclosing definition contexts."*
* **What the code proves:**
  1. [`TyAlgCarrier`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Call.lean) for `Eff` is `Signature Op → TyEnv → Path → Except TypeRefusal EffTy`; it has **no mode flag** (`inLoop : Bool` exists only on `StmtsRes` for generator statements, and `Eff.gen` always initializes `inLoop := false`).
  2. [`Checker.check_rebase`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Typing/Rebase.lean) and [`tableAt_rebase`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Laws/Program/Typing/Rebase.lean) prove:
     $$\text{Checker.check}\;\text{sig}\;\text{env}\;(q \mathbin{++} p)\;e = (\text{Checker.check}\;\text{sig}\;\text{env}\;p\;e).\text{mapError}\;(\text{TypeRefusal.rebase}\;q)$$
     The `Path` parameter has **zero effect on `.ok` outcomes** and acts purely by prefixing `q` on `.error`. Therefore, a typing cache key never needs `path`.

#### Question D: Concurrent edits on strictly disjoint paths (`p = [0]` vs. `q = [1]`)
* **What the review probes ([probes.lean](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/evidence/probes.lean) `C4`, `C6`):**
  `C4` shows that `[0]`'s type determines `[1]`'s environment in `.bind`, and `C6` shows that sequential edits at overlapping paths (`[]` then `[1]`) overwrite without a base check.
* **Sharper result on strictly disjoint (incomparable) paths (executed Probe 4):**
  Consider `baseBind = .bind (.succeed (.lit (.nat 1))) (.succeed (.lit (.nat 2)))` at signature `sig`:
  - **Edit 1 at `[0]`:** replace `[0]` with `editLeftStr = .succeed (.lit (.str "hi"))`. Applied to `baseBind`, the whole program still typechecks with the **same root type** `EffTy.pure .nat` (because `[1]` in `baseBind` does not read `.var 0`), though `[0]`'s local focus type changed from `.nat` to `.string`.
  - **Edit 2 at `[1]`:** replace `[1]` with `editRightReadsNat = .provideService svcKeyB (.var 0) (.succeed (.lit (.nat 2)))` (where `svcKeyB : .nat`). Applied to `baseBind`, this preserves the local focus type at `[1]` (`EffTy.pure .nat`) and the root type.
  - **Merging the two disjoint edits:** Because `[0]` and `[1]` are incomparable paths, [`Node.replaceAt`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/NodeLenses.lean) commutes syntactically (`e1.replaceAt [1] ... = e2.replaceAt [0] ...`), yet the merged program fails `effTy` (`none`) because Edit 1 changed `.var 0` in `[1]`'s environment from `.nat` to `.string`.
  - **Sufficient condition for disjoint-edit composition:** If **both** disjoint edits preserve their respective local [`Focus`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Focus.lean) types (`Sketch.check_fill_focusAt`, i.e., both produce `.spliced` deltas in `EditSession.feed`), then no sibling's [`Node.childEnv`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Program/Typing/Focus.lean) changes (`effTy` on child `0` is invariant), so the combined tree is guaranteed to preserve the root type. If either edit is `.rechecked` (changing its own `EffTy` or `LayerTy`), sibling environments can shift even on disjoint paths.

#### Question E: Running unfinished sketches—what `Tools.Session` already does in `"settle"`, `"frames"`, and `"explore"`
* **What the review says ([README.md](file:///Users/pooks/Dev/lean4-effect4/docs/research/2026-10-17-authoring-model-review/README.md) §3.4, §5):**
  Discusses only `"run"` in [`Tools.Session`](file:///Users/pooks/Dev/lean4-effect4/tools/Tools/Session.lean) and treats executing or exploring sketches with holes as unimplemented.
* **What `Tools.Session` already implements (executed Probe 5A & 5B):**
  [`Tools.Session.answer`](file:///Users/pooks/Dev/lean4-effect4/tools/Tools/Session.lean) already exposes `"settle"`, `"frames"`, and `"explore"`, where it forms `let app := l.app.withHoles l.sketch.holes` and runs [`Effect4.Run.Tree.settle`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Tree.lean), [`Effect4.Run.Tree.frames`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Tree.lean), and [`Effect4.Run.Kit.explore`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Kit.lean) directly on `l.sketch.program`:
  - **Probe 5A (`Tree.settle` at an unfilled hole):** Because `app.withHoles` places hole `k`'s row in `app.rows`, [`Tree.level`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Tree.lean) sees `Eval.inTable table i = true` and emits `call i Val.unit done`. With an empty tape, `Tree.settle` stops at `.waiting 0 Val.unit`—already treating an unfilled hole as a live waiting frontier.
  - **Probe 5B (`Kit.explore` across an unfilled hole):** [`Effect4.Run.Kit.explore`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Kit.lean) calls [`Kit.replies`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Kit.lean) and [`Kit.samples`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Kit.lean) on each hole row in `app.withHoles`, automatically synthesizing admitted sample values (`0, 1, 2` for `.nat`) and exploring all 3 execution paths through the hole to `.finished (.success _)`.
  - **The exact boundary of `"settle"` / `"explore"` vs. `"run"`:** `Run.Tree` covers only the call-tree fragment ([`Tree.covers`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Tree.lean) / [`Tree.armOf`](file:///Users/pooks/Dev/lean4-effect4/src/Effect4/Run/Tree.lean); constructors outside `armOf` such as `provideLayer`, `provideService`, `scoped`, `acquireRelease`, or fiber actions terminate with `done Eval.outside`). Full machine execution (`Effect4.Live` in `"run"`) requires `admitProgram`, which currently fails on any sketch that uses declared services (`C10`) or unfilled holes.
