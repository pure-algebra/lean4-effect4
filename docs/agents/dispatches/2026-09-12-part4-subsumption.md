## Facts checked on 2026-09-12 that shape this lane

- **Atom argument typing is exact today.** `NativeAtom.typeOf` pattern-matches `[.string, .string]`
  for `eq`, `[.nat, .nat]` for `lt`/`add`, etc. Under the ruled literal rule `pair "A" m` types at
  `prod (lit "A") string`, so `fst (pair "A" m)` types at `lit "A"`, and `eq (fst e) "x"` would be
  refused. The ruled rule is "mirror TypeScript", and TypeScript applies assignability at call
  sites, so **subsumption applies at atom arguments too**: a fixed-signature atom accepts an
  argument whose type is a subtype of the expected one (`sub actual expected`); `pair`/`fst`/`snd`
  are polymorphic and unchanged. This is recorded in DI-15 (2026-09-12 clause).
- **Row request and service provision compare by normalized equality today** (`Typing.lean:200`,
  `:294`); both become `sub` (request ⊑ row request; value ⊑ service type). Row answers are unchanged.
- **The prelude `pair` is not const-generic.** `pair = <A, B>(a: A, b: B): readonly [A, B]`
  (prelude.ts:54); TypeScript infers `pair("A", m) : readonly [string, string]`, so the type
  oracle would disagree with Lean's `readonly ["A", string]` on every literal-tagged pair. DI-55
  ruled the const-generic pair in S4b and it never landed. It lands here first:
  `pair = <const A, const B>(a: A, b: B): readonly [A, B]`; with `const` parameters TypeScript
  infers `"A"` for a literal argument and `string` for a `string` variable — exactly the Lean rule.
- **`pIllJoin` stops being ill.** `src/OCaml5/Eff/Goldens.lean:363` is refused today only because
  `nat` and `bool` do not join; under the least-upper-bound rule it types at `union nat bool`.
  `pIllBranch` stays ill (its test is a `nat`). DI-60 requires a widening commit to report the
  count delta and name every program whose verdict changed.
- **Everything that reads `joinAnswer` must move together**: the declarative `HasTy` rules
  (Typing/HasTy.lean), the inversion lemmas (Typing/Inversion.lean :90, :100, :111, :145, :309),
  the generated specs (regenerate), and `effTy_sound`/`effTy_complete`.
- **Atoms are spelled by name on the wire** (`Term.app "eq" args`; `nativeAtomTy` resolves the
  name), so adding `tagIs` changes no ordinal and no wire byte. It needs: the constructor in the
  inductive and in `all`, `name := "tagIs"`, `arity := some 2`, `mono := none` (its second argument
  is polymorphic), eval, `typeOf`, the prelude function, a row in `run-truth.ts`'s self-test
  table, the regenerated OCaml mirror, and the policy covers for every `NativeAtom.*` function
  (the case-site gate goes red until they are named; that is the lock working).
- **`tagIs` is total on values**: `tagIs tag v = some (.bool b)` with `b = true` iff
  `v = .list [.str tag, _]`, and `false` for every other value shape (a bare string, a nat, a
  pair whose first component is not a string). It must never answer `none` on a well-typed
  program, because an error typed `union (prod (lit "A") string) string` can be a bare string.
- **The caught error's index in the test is `env.length`** (`effTy` types the test under
  `env ++ [b.error]`; the fixtures use `.var 0` at the empty environment).
- **`caughtErrorValue?` selects the first `Fail`** (Compile.lean:1205-1207) and re-raises the
  whole cause on a miss. No existing typing-preservation law covers the miss path, so the
  single-`Fail` law below is a new theorem, not a changed one.
- **Canonical error types are in disjunctive normal form since part 1** (no union under a
  `prod` head), so `diffTag` on a canonical form is a member filter.
- **The printed image of a tag catch is `Effect.catchIf(body, (aN) => tagIs("A", aN), handler)`,
  never `Effect.catchTag`**: rc.112's `catchTag` matches `_tag` object fields and our tagged
  errors are tuples, so `catchTag` would not catch them at runtime.
