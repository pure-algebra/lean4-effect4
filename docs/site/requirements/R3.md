# Requirement R3: First-order data types

This page explains requirement R3 in Effect4. It covers what the requirement asks for records and variants, why structured data types matter, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R3 asks that the static type language `Ty` closes under structured first-order data types (`docs/core/system-map.md` §8, DB-15):
- Records: represented by a single constructor over field lists sorted in canonical name order (decisions row 119).
- Variants: tagged union representations with normalized membership (decisions row 130).
- Maps and tuples: pointwise and key-indexed compound data structures.

Every added constructor must provide its `Fits` membership rule, exact codecs, catamorphic folds, assignability order, and inhabitance characterization.

## Why it matters {#why-it-matters}

Application workflows manipulate rich domain models including structured records, optional attributes, error payloads, and payload classes.

If the type system lacked direct representations for compound data, applications would need informal encodings that escape verification.

Closing `Ty` under records and variants provides thorough end-to-end verification for realistic application data structures.

## How it is checked {#how-it-is-checked}

The requirement is checked by proving algebra, membership, codec, and inhabitance theorems across all constructors:
- Value membership under normalization is stated by `fits_normalize` and `fits_subN` (`src/Effect4/Laws/Program/Typed/Membership.lean`).
- Semantic inhabitance equivalence is stated by `inhabited_iff_fits` in the same file.
- Exact serialization embeddings are stated by `decode_iff` (`src/Effect4/Laws/Schema/Codec.lean`) and `ofSchema_exact` (`src/Effect4/Schema/Bridge.lean`).
- Error payload round-trip fidelity is stated by `errOf_valOfErr` (`src/Effect4/Laws/Program/Admit.lean`).

The plan on this page gives each theorem's status and the goals it rests on.
