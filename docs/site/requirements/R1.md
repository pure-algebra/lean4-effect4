# Requirement R1: The typing signature is a parameter

This page explains requirement R1 in Effect4. It covers what the requirement asks about signature parameterization, why open signatures matter for extensible applications, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R1 demands that the language typing signature Σ remains an explicit parameter across all milestone statements and verification layers (`docs/core/system-map.md` §8).

The specification requires:
- Program admission checks the application signature via `AdmittedSig Σ` and `admitSig_ok_iff`.
- The typed machine state reads the source's signature dynamically.
- Core typing theorems and milestone statements take the signature as an explicit hypothesis.

The runtime must not hard-code operations to a closed built-in set.

## Why it matters {#why-it-matters}

Real-world Effect applications define custom operations, host integrations, and application services.

If semantic theorems assumed a fixed operation signature, application-defined effects would lack formal verification.

A signature that is a parameter lets an application add operations, and every milestone statement then takes the application's signature.

## How it is checked {#how-it-is-checked}

The requirement is checked by proving that typing and evaluation hold for an admitted signature:
- Algorithmic soundness and completeness against `HasTy` (`check_sound`, `check_complete`) quantify over any lawful typing signature in `src/Effect4/Laws/Program/Typing/CheckSound.lean`.
- Signature admission equivalence is stated by `admitSig_ok_iff` (`src/Effect4/Program/SigApp.lean`).
- Operational typing across application signatures is stated by `meaning_typed_app` and `run_typed_app` (`src/Effect4/Laws/Program/SoundAnySignature.lean`).

The plan on this page gives each theorem's status and the goals it rests on.
