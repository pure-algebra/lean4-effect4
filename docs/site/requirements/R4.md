# Requirement R4: Stateful memory and row templates

This page explains requirement R4 in Effect4. It covers what the requirement asks for mutable cells and row templates, why stateful typing matters, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R4 demands that the typed world supports mutable cells at arbitrary types and models operation rows as templates (`docs/core/system-map.md` §8):
- World typing: `World` explicitly tracks types for cells (`w.Ρ`), deferred promises (`w.Π`), fibers (`w.Γ`), and tokens (`w.Θ`).
- Row templates: operation rows act as templates whose type parameters instantiate via match by bounds.
- Binder terms: function rows take first-order binder terms that map cell types under environment extensions.

Allocating a fresh cell or promise must extend the world monotonically without invalidating earlier allocations.

## Why it matters {#why-it-matters}

Concurrent programs coordinate across fibers using shared mutable state, asynchronous promises, and synchronized queues.

If stateful references supported only primitive numbers or hard-coded payload types, applications could not manage complex state.

Matching row templates by bounds lets a generic operation take its type arguments from the program, before the run.

## How it is checked {#how-it-is-checked}

The requirement is checked by proving world extension, template matching, and step typing theorems:
- World order reflexivity and transitivity are stated in `src/Effect4/Laws/Program/Typed/World.lean`.
- Allocation monotonicity is stated by `refMake_extension` and `deferredMake_extension` in the same file.
- Totality of template matching by bounds is stated by `Bounds.matchB_complete` (`src/Effect4/Laws/Program/Bounds.lean`).
- Atomic update typing is stated by `fold_typed_atomic_update` (`src/Effect4/Laws/Program/Typed/ListFold.lean`).

The plan on this page gives each theorem's status and the goals it rests on.
