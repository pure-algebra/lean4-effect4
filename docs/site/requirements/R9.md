# Requirement R9: Well-typed programs never go wrong

This page explains requirement R9 in Effect4. It covers what the requirement asks for type safety and defect exclusion, why non-halting matters, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R9 formalizes type safety by proving that every typed program execution satisfies `ExitOk` and never halts (`docs/core/system-map.md` §8, DB-16):
- Exit correctness: `ExitOk w ty ex := FitsExit w ty ex ∧ NoShapeDefect ty ex` holds at every typed exit position.
- Shape defect exclusion: `NoShapeDefect` excludes reserved malformed code defects such as `badName` and `notImplemented` (decisions row 107).
- Non-halting: the small-step transition system never encounters a stuck configuration (`machineTyped_not_halted`).

The property is scoped to `M7Fragment`: a lawful source, an empty row table, an admitted closed program, and an answer-free tape.

## Why it matters {#why-it-matters}

Type systems aim to prove that well-typed programs cannot go wrong (Milner 1978).

In untyped JavaScript, unhandled shapes, missing services, and internal runtime bugs cause unexpected crashes.

Requirement R9 asks that a checked program end in a value or a typed cause, and never halt the machine.

## How it is checked {#how-it-is-checked}

The requirement is checked by assembling the milestone proofs M5, M6, and M7:
- The route theorem `m7_of_ledger` states that load typing (M5) and the preservation of `ConfigTyped` by each command (M6) imply milestone M7 (`src/Effect4/Laws/Program/Typed/Assembly.lean`).
- The theorem `machineTyped_not_halted`, in the same file, states that a typed machine is never halted.
- Milestone results are stated by `m7_proved` in `src/Effect4/Laws/Program/Typed/Commands/Clauses/All.lean`.
- Source program admission connecting checked programs to M7 is stated by `m7_admitted` (`src/Effect4/Laws/Program/Typed/AdmittedSource.lean`).

The plan on this page gives each theorem's status and the goals it rests on.
