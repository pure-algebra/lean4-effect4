# Requirement R10: Composed libraries inherit theorems

This page explains requirement R10 in Effect4. It covers what the requirement asks for library forms, why behavioral inheritance matters for composite modules, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R10 demands that high-level library modules inherit formal theorems from their underlying primitive representations (`docs/core/system-map.md` §8, decisions row 79, DI-89):
- Agreement laws: each composed module satisfies `Agrees profile module expansion` on a named profile.
- Form obligations: every authoring form owes a typing lemma, a behavior law, lexical scoping, module reader admission, and a stable identity.
- Expansion stability: composite modules like Queue, Pool and Semaphore state step agreement against their primitive expansions.

High-level library utilities must not introduce unvetted runtime primitives.

## Why it matters {#why-it-matters}

Effect provides extensive library modules for concurrent data structures, synchronization primitives, and resource pools.

If composite modules were treated as black boxes with hand-written runtime implementations, their correctness could not be formally assured.

Behavioural agreement is what lets library code take the core language's typing and simulation theorems, where each is proved.

## How it is checked {#how-it-is-checked}

The requirement is checked by proving form typing lemmas and step agreement laws for library structures:
- Form typing lemmas for combinators like `andThenEffect`, `ensuring`, and `forkScopedDefault` are stated in `src/Effect4/Laws/Codegen/Forms.lean`.
- Step agreement laws relating composite modules to primitive expansions are stated for `Latch`, `Pool`, `PubSub`, `Queue`, `Ref`, and `Semaphore` in their respective profile modules.
- Stream array step agreement is stated by `arrayStep_agrees` (`src/Effect4/Laws/Library/Stream/Array.lean`).

The plan on this page gives each theorem's status and the goals it rests on.
