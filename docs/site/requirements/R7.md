# Requirement R7: Retained behaviour

This page explains requirement R7 in Effect4. It covers what the requirement asks for stored code entries, why typed code resolution matters, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R7 demands that stored code behaviors resolve into typed entries with fixed capture layouts (`docs/core/system-map.md` §8, `docs/core/machine-state.md` §5):
- Typed resolution: a resolved code entry is typed at its reference type through `resolve_typed`.
- Fixed capture layout: captured services and environment variables fix their layout at resolution.
- Stable identity: code entry identity is established by allocation or structural equality.
- Owner resolution: stored behavior references resolve into the canonical `Eff` program owner rather than storing host closures.

Captured control state and reusable behavior content must remain distinct syntactic sorts.

## Why it matters {#why-it-matters}

Advanced Effect modules like PubSub, Mailbox, and actor pools store and dispatch deferred execution tasks.

If stored behaviors captured arbitrary host closures, internal execution state would leak into value sorts and defeat reification.

Typed first-order resolution lets a stored routine be serialized, replayed and checked across runs.

## How it is checked {#how-it-is-checked}

The requirement is checked by formalizing code resolution and capture typing contracts:
- Code entry typing is governed by the `resolve_typed` specification connecting code references to target typing signatures.
- Posted body entry typing asks that a queued task run under a fitting environment (decisions rows 82 and 225).
- Reserved contracts for retained behavior prevent execution details from freezing into data values (decisions row 234).

The plan on this page gives each theorem's status and the goals it rests on.
