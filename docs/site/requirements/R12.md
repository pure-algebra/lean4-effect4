# Requirement R12: Frontiers name what they await

This page explains requirement R12 in Effect4. It covers what the requirement asks for live frontiers, why distinguishing waiting from deadlocks matters, and how the property is checked.

## What the requirement asks {#what-it-asks}

Requirement R12 demands that non-terminal machine states explicitly name what they await rather than conflating pauses with failures (`docs/core/system-map.md` §8, DB-03):
- Live frontiers: a frontier state represents a live pause waiting for fuel, host replies, or scheduling decisions.
- Frontier characterization: when execution runs out of decisions, the frontier is empty if and only if the machine is deadlocked (`frontier_empty_iff_deadlocked`).
- Deadlock definition: `Deadlocked` requires no runnable fiber, no armed listener, no pending host request, no active timer, and no compile budget.
- Fairness draining: a fair decision tape leaves no armed listener at its live end (`fairTape_unarmed`).

A pause caused by resource exhaustion or external silence must never be reported as an error.

## Why it matters {#why-it-matters}

Asynchronous and concurrent systems pause frequently when waiting for external responses or when running out of budgeted time.

If a runtime treated pauses as deadlocks or exceptions, programs would fail prematurely during legitimate long-running tasks.

Naming frontier causes allows external drivers to supply appropriate budget, deliver host replies, and resume paused fibers cleanly.

## How it is checked {#how-it-is-checked}

The requirement is checked by proving frontier characterization, deadlock criteria, and fair tape draining theorems:
- Deadlock characterization is stated by `frontier_empty_iff_deadlocked` in `src/Effect4/Laws/Api/Frontier.lean`.
- Fair tape draining of armed listeners is stated by `fairTape_unarmed` (`src/Effect4/Laws/Machine/Scheduling.lean`).
- Loop frontier characterization under host reply tapes is stated by `rows_loop_frontier` (`src/Effect4/Laws/Api/SessionMeaningLoop.lean`).
- Meaning frontiers under silent hosts are stated by `rows_loop_frontier_host` in the same file.

The plan on this page gives each theorem's status and the goals it rests on.
