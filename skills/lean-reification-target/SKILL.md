# Connect a reified program to its target

Require the source/target domains, admitted profile, observations, and allowed
edits. Keep source ingestion, semantic interpretation, and code generation
distinct. A generated target does not become the authority for its source's
meaning. Read [boundary obligations](references/boundaries.md) for the relevant
encoding, compiler, or execution branch.

## Specify each transformation

Record the actual chain: external source or raw data, admission, checked
program, semantic interpretation, typed target data, rendered bytes, parsed
target, and hosted execution. Omit stages that do not exist; mark claimed but
unimplemented arrows open. For each arrow name total/partial behavior,
normalization or information loss, theorem/checker, and the observation it
supports. Use [the boundary record](assets/boundary-record.md) if needed.

Choose exactness deliberately. A left inverse does not establish both
round-trips; a decoder accepting additional spellings does not preserve raw
identity; a canonical-normal-form recognizer is not a semantic quotient map.
State compiler refinement with explicit quantifiers. Preserving each source
run alone does not exclude extra bad target runs in a nondeterministic target.

For generated code, use a typed target representation when it makes the
admitted grammar inspectable. Isolate raw text escape hatches and require
evidence that checked lowering cannot reach them. Source rendering's repeat-call
determinism says little about correctness; inspect parsing, name capture,
escaping, normalization, and any required injectivity separately.

## Generate the promised surface

Generate executable predicates and traversals from the canonical semantic
definition or a checked intermediate description when that is the requested
counterpart. A handful of fixtures or a handwritten duplicate recursion is
not the full generated predicate. Independently account for every constructor,
recursive field, overload, alias, and admitted foreign reference in scope.

Retain raw distinctions until the contract permits their loss: duplicate keys,
entry order, missing versus empty values, reference identity, numeric bit
patterns, and failure-side state. Registry entries crossing into host code
must bind stable identities to types, capabilities, and the assumed behavior.

## Verify the right boundary

Separate these evidence types:

1. Lean proof of the transformation or interpretation relation.
2. Deterministic regeneration and byte comparison with declared inputs.
3. Structural decode or validation relating this target to this source.
4. Typechecking and tool diagnostics over the exact generated file set.
5. Runtime observations against the pinned host and declared oracle.

Tests generated by the same faulty traversal can agree. Include an independent
source census or observer and planted omissions. Do not call a validator
verified without its acceptance-implies-relation theorem. A universal compiler
theorem and per-artifact translation validation are different assurance routes.

Pin source revision, installed package bytes, compiler, runtime, diagnostics,
profile, and inputs separately where they matter. Check nonempty discovery,
exact file/case coverage, and detected versions. Exercise relevant positive
controls and meaningful wrong targets in isolation; verify rejection by the
intended check, followed by acceptance after restoration.

## Finish

Deliver the target artifacts, regeneration command, boundary receipts, tested
observations, and remaining assumptions. Bounded host agreement stays bounded;
testing does not close an unproved simulation or every future environment.
Retire a source owner or declare cutover only through the project's explicit
completion rules. For a documentation-only task, deliver this record without
generating or executing a program outside the authorized scope.
