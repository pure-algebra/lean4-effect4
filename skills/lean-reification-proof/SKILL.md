# Prove the frozen connection

Start from the approved statement, referenced semantic definitions, imports,
toolchain, allowed dependencies, edit fence, and breaker cases. If these are
unsettled, use [Contract](../lean-reification-contract/SKILL.md) to expose the
missing decision; do not solve a different theorem.

## Inspect the obligation

Check the exact declaration type, universes, implicit arguments, namespaces,
instances, and reducible definitions at the target pin. Recover evidence from
the current files, not an old transcript. Record the statement and dependency
snapshot so a proof cannot succeed by changing what the statement means.

For reification, separate the obligations actually needed:

- successful admission yields well-formed data and the promised source relation;
- checked erasure, encoding, decoding, and normalization satisfy their stated
  directions on their stated domains;
- handlers respect operations as well as the required composition laws;
- interpreter or modality claims use the actual state/history and outcomes;
- runner results correspond to the relational meaning with explicit bounds;
- target simulations transport the required observation in the right direction.

Read [proof and trust decisions](references/proof-and-trust.md) when selecting
proof structure, inspecting axiom dependencies, or separating certificates
from external computation. Consult existing local lemmas before proposing new
public abstractions.

## Develop the proof

Choose induction on syntax, an execution derivation, or a transition invariant
according to the claim. Use coinduction only through a supported representation
and the project's admitted dependencies. Decompose a failed bridge into local
steps that still imply the original goal; keep the end-to-end obligation open
until the composition theorem is present.

Use reduction and the project's existing theorem/automation library before
expanding model search. Give a model the exact failing goal, available facts,
and current error. Make one meaningful local repair, retain checked portions,
and recheck the saved artifact. When search stalls, test the statement with
[Breaker](../lean-reification-breaker/SKILL.md) before spending more attempts.
Use a task-proportionate search budget; exhaustion never licenses weaker
assumptions, a new axiom, or replacement of an executable definition by an oracle.

Changes to a frozen theorem, its semantic definitions, or trust policy return
to the contract owner with the old/new meaning and supporting evidence. Added
helper lemmas must be proved and stay within the edit fence. Temporary proof
holes and unproved obligations never count as completed evidence.

## Accept the saved result

Run the narrow contract and required project build/gates. Inspect the exact
exported declarations and their transitive axiom dependencies, including
generated instances and private auxiliaries where they influence the claim.
Use `#print axioms` and the repository's compiled-declaration audit; source
search alone cannot establish this. Check that the intended positive and
negative cases still exercise the same definitions.

Native evaluation and `Classical.choice` have different trust implications;
apply the project's policy and exact toolchain behavior, not a universal ban
or a remembered axiom-name list. Do not broaden an exception merely because
the current proof reaches it. Report an unrelated full-build failure alongside
the narrow result, with the resulting limit on acceptance.

Finish with the saved proof, unchanged/authorized statement record, commands
and results, dependency receipt, and open connections. Use
[the proof receipt](assets/proof-receipt.md) when the project has none. A theorem
about a model does not certify generated bytes or a JavaScript runtime; route
those remaining obligations to [Target](../lean-reification-target/SKILL.md).
