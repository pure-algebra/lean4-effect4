# Reification attack catalogue

Select the rows relevant to the claim. The purpose is a decisive witness, not
an obligation to run every attack on every task.

| Mechanism | Small challenge | Required discrimination |
| --- | --- | --- |
| Vacuous acceptance | A checker always returns refusal | Soundness can hold while the promised valid witness is rejected |
| Vacuous theorem | Preconditions are inconsistent or the quantified domain is empty | A positive witness must inhabit the intended domain |
| Weakened observation | Two runs differ only in failure-side state or order | The selected observation must retain the promised distinction |
| Missing recursion | Put one invalid reference inside an annotation's nested schema inside a check | Every semantic child route is visited, with order/multiplicity when observable |
| Data loss at ingress | Duplicate keys separated by an unrelated entry; missing versus present-empty | Validation precedes destructive normalization and obeys the chosen policy |
| Hidden code | A purported stored node captures a host closure or ambient mutable value | Durable identity binds code and captures, or the form is refused/foreign |
| Broken scope | A child block captures a value outside its declared environment | Admission or the execution relation exposes the invalid capture |
| Empty sequence | Empty prefix with a nonempty suffix | Composition uses its actual domain, rather than assuming a table is a monad |
| Restarted suffix | The suffix refers to an answer produced by the prefix | The composition rule threads the prefix history |
| Lost state | Body writes state then fails; cleanup observes that state | Failure result retains the information promised to cleanup |
| Skipped cleanup | Put cleanup after failure via ordinary short-circuiting bind | Finalization is exit-aware and covers the claimed exits |
| Duplicated continuation | Resume twice after acquiring a one-shot resource | Multiplicity policy and ownership are enforced |
| Fuel confusion | Same admitted program with too little and enough fuel | Unfinished execution is distinct from failure and stable completion |
| Choice erasure | Same initial state with two permitted replies | Unfixed choices cannot support an unconditional unique-result claim |
| Fairness overclaim | A permitted scheduler repeatedly ignores one enabled action | Safety evidence does not establish eventual service |
| Wrong simulation direction | Target allows a safe source trace plus one extra bad trace | The required safety-transfer direction rules out the extra behavior |
| One-sided codec | Decoder accepts many raw spellings but encoder selects one | Exact raw reconstruction needs its own law or a stated normalization |
| Nonsemantic classifier | Observationally equal programs have distinct dependency graphs | Conservative structural information need not be equality-invariant |
| Wrong layer | Wire decoding succeeds but later reference revival fails | Acceptance is attributed to the exact host layer |
| Circular oracle | Generator and expected output use the same omitted-field walk | An independent census or observer detects the omission |
| Empty tool run | No files discovered or wrong package version detected | Coverage/version checks reject before claiming conformance |
| Inert detector | A mutant fails to parse before the trust check runs | The intended detector must actually run and name the violation |
| Broad exception | Add an unapproved semantic declaration beside an approved renderer | Exception scope cannot silently expand to neighboring declarations |

## Witness quality

Keep the decisive pair when the defect is information loss: same retained
representation, different required observation. It demonstrates why changing
only the proof cannot repair the claim. Retain a repaired positive boundary,
such as history-threaded sequencing or a fixed compatible decision tape.

When a branch has many fields or recursive routes, use distinguishable values
or labels so omission, duplication, and reordering have different outputs.
Checking only that a traversal terminates misses all three.

Record whether a witness is a theorem, an executable observation, a bounded
model, or an unverified sketch. An old report without its original fixture is
historical evidence; a newly passing repaired harness does not retroactively
reproduce the lost counterexample.

## Isolated detector test

Record the original content digest, positive control, planted defect, expected
detector, observed diagnostic/exit, and restored result. Use an isolated copy
for mutations. A generic nonzero exit is insufficient where a specific gate
must reject the defect. Excluded modules, parser errors, and stale known-red
lists are limits or defects in the audit, not successful rejection tests.
